# 汉化助手 — Unity 游戏本地化工具

本地模型驱动的 Unity 游戏汉化工具：`扫描识别 → 批量翻译 → 质量检查 → 安全写回 → 经验积累` 全流程闭环，完全离线运行。
与「原文丢给模型」的单向翻译不同，本项目以**质量保障为核心**：规则、记忆、知识库层层把关，让翻译不是一次性的输出，而是可验证、可积累的工程。

---

## 特色与优势

| 优势 | 说明 |
|---|---|
| **纯本地离线** | 翻译模型（Hy-MT2-1.8B）随包运行，文本不上传任何服务器——无额度限制、无隐私顾虑、无网可用 |
| **模型驱动 + 规则护航** | 翻译交给模型，但每条译文都过确定性规则、术语库、记忆库检查；模型负责「翻译」，规则负责「不翻坏」 |
| **全流程自动化** | 检测 → 扫描 → 分析 → 翻译 → 写回 → 重开验证，一条命令跑完，全环节留档可审计 |
| **越用越熟** | 跨游戏经验记忆（AgentMemory）+ 术语库 + 六库知识库自动沉淀——处理过的游戏越多，可复用的积累越多 |
| **安全写回** | 只写回「质量通过 + 置信度合格」的译文；写回后重开游戏文件逐条核对，不假报成功 |
| **零配置发行包** | 内置 Python 3.12 与 llama.cpp 运行时，解压双击即用 |

## 快速开始（用户）

**发行包**：解压后双击根目录「启动汉化助手.bat」→ 设置页选翻译后端（本地 Hy-MT2 / 在线 API）→ 拖入游戏文件夹 → 五步工作台 → 写回成功后点「开始游戏」。

**开发环境**：

```bash
pip install -r requirements.txt
python main.py
```

**命令行排查**（免界面全流程 + 全环节记录）：

```bash
python scripts/all_record_runner.py "<游戏目录>" --no-review
# 输出：docs/all record/<游戏>/（summary.md + text/ + writeback/）
```

## 工作流程（一次汉化怎么完成）

| 步骤 | 做什么 | 质量保障 |
|---|---|---|
| **① 检测** | 识别 Unity 版本与文本存放方式（本地化文件/程序集/打包数据） | 未知 runtime/版本显示 blocked，不假装识别成功 |
| **② 扫描** | 找出所有可改文本并记录位置与格式 | 未知文本形态告警留档（L1-L8 证据分层） |
| **③ 分析** | 判定哪些该翻、哪些不能碰（引擎配置/按键名/代码逻辑字符串——翻错会坏游戏） | 词表对象（打字游戏单词库）、TMP 资产、输入绑定路径整体跳过 |
| **④ 翻译** | 逐条：查记忆（以前翻过没有）→ 查术语/知识库 → 模型翻译 → 质量门检查 | 失败原因分类 + 定向重译（attempt 预算防死循环） |
| **⑤ 写回** | 译文按原格式写回游戏文件，重开比对逐条核对 | 文件/容器/对象/运行时四态闸门 + 原子发布 |

## 质量保障体系（核心特色）

### 翻译时的三道关

1. **记忆关** — 翻过的**一模一样**文本直接复用，前后一致不重复翻译
2. **规则关** — 20+ 确定性检查（详见下节）
3. **经验关** — 跨游戏记忆 + 术语库 + 知识库注入翻译上下文

### 硬规则检查（20+ 项，示例）

- **结构安全**：占位符（`{player}`/`%s`/`{0}`）不丢、富文本标签（`<color>`/`<b>`）不坏、换行/数字/控制字符不变
- **按键名保护**：RMB→「右键」、SPACE→「空格」可译通称；译没了玩家找不到键
- **半翻译拦截**："TOSS TRASH"→「TOSS 垃圾」判失败重译
- **词对防污染**：TIME→时间 不误杀 "time to"→是时候（需标签语境才命中）
- **对象级跳过**：词表对象、TMP 字体/精灵、输入绑定、引擎配置——翻译即破坏玩法/断引用

### 经验记忆（AgentMemory）

只收质量门通过且非回显的译文 → 多次一致证据晋升 active → 高置信直接应用（仍过质量门复查）、一般置信注入 prompt 参考 → 被拒绝的记忆降级直至退休。语境冲突可审计。

## 支持范围（客观陈述）

### 文本来源

| 来源 | 提取 | 写回 | 说明 |
|---|---|---|---|
| 本地化文件（JSON/CSV/TSV/XML/TXT/INI） | ✅ | ✅ | 保留原编码与换行策略 |
| TextAsset（含老 Unity 4.x/5.x str 字段） | ✅ | ✅ | 可变长重建 + 重开验证 |
| MonoBehaviour 序列化字符串 | ✅ | ✅ | 对象级重开验证 + 逻辑键 revert 防线 |
| Addressables（Unity Localization 表） | ✅ | ✅ | 按 Entry ID 写回 + catalog CRC 同步 |
| Mono 程序集（C# #US 堆） | ✅ | ✅ | 受原容量限制，超长译文截断并报告 |
| IL2CPP global-metadata.dat | ✅ | ✅ | 仅已验证部分版本（v24/27/29/31/39），全池重开比对 |

### 边界说明

- 已处理游戏样本覆盖多种 Unity 版本与打包方式，但**样本覆盖不等于所有 Unity 游戏通用**；未知版本显示 blocked 而非假报成功
- **不可汉化**：运行时拼接/加密文本、服务器下发文本、贴图内文字（需 OCR，超范围）；位图字体（.fnt）游戏被正确阻断
- 字体注入仅限 Windows x64 Mono；IL2CPP/x86 即使能提取文本，也不保证中文显示

## 当前局限（客观陈述）

### 识别

- 运行时拼接/加密、服务器下发、贴图内文字**无法识别**（需 OCR，超范围）
- 未知文本形态存在漏识别可能——有告警留档机制，但不保证全覆盖
- 部分来源受引擎版本/打包方式限制，可能只能识别部分文本

### 翻译质量

- 主模型 1.8B 属小模型：复杂句式、文学性表达、俚语翻译质量有限
- **多义词/语境词容易译错**（实证：PRESS→「媒体」；菜单语境 RESUME 被误译）——词面正确但意思不对
- 语义错译目前无自动化拦截（质量门只查形式），修复计划见「近期计划」

### 写回风险（实证案例）

- 写回可能破坏游戏：实证中曾把引擎配置文件（boot.config）当普通文本翻译，导致引擎解析失败（dollhouse）；引擎配置对象被翻译导致输入失效（morfosigame）——已通过「引擎配置跳过」修复，但**同类未知配置仍有风险**
- 固定容量写回（Mono #US / IL2CPP 池）：译文过长被截断，显示可能不完整
- 写回验证到「重开比对」为止，**不保证游戏内运行表现**

### 验证方式

- 不做实机测试：UI 布局溢出、字体渲染等运行期问题可能漏检
- 闭环验证 = 扫描 → 翻译 → 写回 → 重开比对，不含游戏内游玩验证

## 近期计划：加入其他模型提高翻译质量

当前质量门拦得住「形式错」，拦不住「意思错」。近期计划把**审核模型加入翻译链路**，让工具「看得懂上下文」：

| # | 计划 | 解决的问题 |
|---|---|---|
| 1 | **Qwen3-4B 深度审核**：译文按 PASS/MINOR/MAJOR/CRITICAL 四级分级，错误带理由自动重译 | 语义错译（PRESS→媒体 类）的自动化拦截 |
| 2 | **游戏语境库**：记录「这句在什么场景下出现」，多义词按场景翻译 | Resume/Save/Load 不再翻错 |
| 3 | **Reranker-0.6B 语境匹配**：翻译参考只选最相关的候选 | 避免参考错内容 |
| 4 | **Embedding-0.6B 向量检索**：相似文本自动召回，重复文本直接复用 | 翻译更快、一致性更好 |
| 5 | **错误案例自动学习**：错误按类型统计，高频错误生成规则建议 | 同类错误不再重复出现 |

详细技术方案（模型选型/数据结构/任务清单/验收标准）见 **`docs/翻译质量保障系统实施计划.md`**。

## 架构与开发（开发者）

### 总体架构

```
┌────────────────────────── 界面层（PySide6） ──────────────────────────┐
│  五步工作台（检测→扫描→分析→翻译→写回）· 设置 · 开始游戏               │
└──────────────────────────────┬───────────────────────────────────────┘
                               ▼
┌────────────────────────── 核心层（与界面解耦） ────────────────────────┐
│  提取：UnityPy / dnfile / IL2CPP 原生解析 + Il2CppDumper 交叉验证      │
│  翻译：BatchTranslator（记忆直填 → 术语/知识注入 → 模型 → 质量门）      │
│  质量：validate_translation_quality（20+ 硬规则 + 失败原因分类）        │
│  审核：SemanticReviewer（强模型五维，默认关闭，规划接入生产）           │
│  写回：四态闸门（文件/容器/对象/运行时）+ 重开验证 + 原子发布           │
│  知识：GlossaryStore（术语）· KnowledgeStore（六库）· AgentMemory      │
└──────────────────────────────────┬────────────────────────────────────┘
                                   ▼
┌────────────────────────── 运行时与外部工具 ────────────────────────────┐
│  llama.cpp（本地模型）· Il2CppDumper · BMFont · 字体回退插件（C#）      │
└────────────────────────────────────────────────────────────────────────┘
```

### 核心模块

| 模块 | 职责 |
|---|---|
| `core/unity/` | 六类文本来源的提取与写回（UnityPy / dnfile / IL2CPP） |
| `core/quality.py` | 质量门：20+ 硬规则 + 失败原因分类（input_token→key_name→glossary→action_word→untranslated 优先级链） |
| `core/batch_translator.py` | 批量翻译主流程：记忆直填、上下文注入、重试链、attempt 预算 |
| `core/reviewer.py` | 语义审核基础设施（强模型五维审核，默认关闭） |
| `core/agent_memory.py` | 经验记忆：证据驱动晋升/退休 |
| `core/memory.py` | 项目存储 + 会话级翻译记忆 |
| `core/knowledge.py` | 六库知识库（unity_structure/fail_case/text/component_compat/quality/writeback） |
| `core/glossary.py` | 术语库（含冲突检测） |
