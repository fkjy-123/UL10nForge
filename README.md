# 汉化助手 — Unity 游戏本地化工具

本地模型驱动的 Unity 游戏汉化工具：`扫描识别 → 批量翻译 → 质量检查 → 安全写回 → 经验积累` 全流程闭环，完全离线运行。与「原文丢给模型」不同，本项目以**质量保障为核心**——规则、记忆、知识库层层把关，翻译不是一次性输出，而是可验证、可积累的工程。

---

## 特色与优势

- **纯本地离线**：翻译模型随包运行，文本不上传任何服务器——无额度、无隐私顾虑、无网可用
- **模型驱动 + 规则护航**：模型负责翻译，规则负责「不翻坏」——每条译文都过确定性检查
- **全流程自动化**：检测 → 扫描 → 分析 → 翻译 → 写回 → 重开验证，全环节留档可审计
- **越用越熟**：跨游戏经验记忆 + 术语库 + 知识库自动沉淀
- **安全写回**：只写回「质量通过 + 置信度合格」的译文，重开核对，不假报成功
- **零配置发行包**：内置 Python 3.12 与 llama.cpp，解压双击即用

## 快速开始

```bash
# 发行包：解压后双击「启动汉化助手.bat」→ 拖入游戏文件夹 → 五步工作台 → 写回后「开始游戏」
# 开发环境：
pip install -r requirements.txt && python main.py
# 命令行排查（免界面全流程 + 全环节记录）：
python scripts/all_record_runner.py "<游戏目录>" --no-review
```

## 工作流程

| 步骤 | 做什么 |
|---|---|
| ① 检测 | 识别 Unity 版本与文本存放方式；未知 runtime/版本显示 blocked，不假装成功 |
| ② 扫描 | 找出所有可改文本；未知形态告警留档（L1-L8 证据分层） |
| ③ 分析 | 判定哪些该翻、哪些不能碰——引擎配置/按键名/代码逻辑字符串翻错会坏游戏（有实证），词表对象、TMP 资产、输入绑定整体跳过 |
| ④ 翻译 | 查记忆 → 查术语/知识库 → 模型翻译 → 质量门检查；失败原因分类 + 定向重译 |
| ⑤ 写回 | 按原格式写回，重开比对逐条核对；四态闸门（文件/容器/对象/运行时）+ 原子发布 |

## 质量保障

每条译文过**三道关**：

1. **记忆关** —— 翻过的一模一样文本直接复用，前后一致
2. **规则关** —— 20+ 确定性检查：占位符（`{player}`/`%s`）不丢、富文本标签不坏、数字不误改、按键名保护（RMB→「右键」可以，译没了玩家找不到键）、半翻译拦截（"TOSS TRASH"→「TOSS 垃圾」重译）
3. **经验关** —— AgentMemory：只收质量门通过的译文，证据驱动晋升 active，被拒降级退休；术语库/六库知识库注入翻译上下文

## 支持范围（客观）

| 文本来源 | 提取 | 写回 |
|---|---|---|
| 本地化文件（JSON/CSV/TSV/XML/TXT/INI） | ✅ | ✅ 保留编码与换行 |
| TextAsset（含老 Unity 4.x/5.x） | ✅ | ✅ 可变长重建 + 重开验证 |
| MonoBehaviour 序列化字符串 | ✅ | ✅ 对象级重开验证 |
| Addressables（Unity Localization 表） | ✅ | ✅ Entry ID 写回 + CRC 同步 |
| Mono 程序集（C# #US 堆） | ✅ | ✅ 受原容量限制，超长截断并报告 |
| IL2CPP metadata | ✅ | ✅ 仅验证过 v24/27/29/31/39 |

边界：已处理样本覆盖多种 Unity 版本与打包方式，但**不等于所有 Unity 游戏通用**；不可汉化的（运行时拼接/加密/服务器下发/贴图文字/位图字体）明确阻断不假报；字体注入仅限 Windows x64 Mono，IL2CPP/x86 不保证中文显示。

## 当前局限（客观）

- **识别**：拼接/加密/服务器下发/贴图内文字无法识别（需 OCR）；未知形态可能漏识别（有告警留档，不保证全覆盖）
- **翻译质量**：1.8B 属小模型，复杂句/文学性表达质量有限；多义词易错（实证：PRESS→「媒体」、菜单语境 RESUME 误译），语义错译目前无自动化拦截
- **写回风险**：实证曾把引擎配置文件当普通文本翻译导致解析失败（dollhouse）、引擎配置对象被翻导致输入失效（morfosigame）——已修复但同类未知配置仍有风险；固定容量写回译文过长会截断
- **验证局限**：闭环验证到「重开比对」为止，不做实机测试——UI 溢出、字体渲染等运行期问题可能漏检

## 近期计划：加入其他模型提高翻译质量

当前质量门拦得住「形式错」，拦不住「意思错」。计划把审核模型加入链路：

1. **Qwen3-4B 深度审核**——译文分 PASS/MINOR/MAJOR/CRITICAL 四级，错误带理由自动重译（拦语义错译）
2. **游戏语境库**——记录「这句在什么场景下出现」，多义词按场景翻译（Resume/Save 不再翻错）
3. **Reranker-0.6B 语境匹配**——翻译参考只选最相关的候选
4. **Embedding-0.6B 向量检索**——相似文本自动召回，重复文本直接复用
5. **错误案例自动学习**——高频错误生成规则建议，同类错误不重复犯

详细方案见 **`docs/翻译质量保障系统实施计划.md`**。

## 架构与开发

```
界面层（PySide6 五步工作台）
    │
核心层（与界面解耦）：提取（UnityPy/dnfile/IL2CPP）→ 翻译（记忆直填→模型→质量门→重试链）
    │                    → 写回（四态闸门+重开验证）→ 知识（术语库/六库/AgentMemory）
    │
运行时：llama.cpp（本地模型）· Il2CppDumper · BMFont · 字体回退插件
```

```
hanhua/
├── core/                  # 核心层：解析/翻译/质量/存储/写回
│   ├── unity/ tooling/    # 提取写回与外部工具编排
│   ├── quality.py         # 质量门（20+ 硬规则 + 失败原因分类）
│   ├── batch_translator.py# 批量翻译主流程
│   ├── reviewer.py        # 语义审核（强模型五维，默认关闭，规划接入生产）
│   ├── agent_memory.py    # 经验记忆（证据驱动晋升/退休）
│   ├── memory.py knowledge.py glossary.py   # 项目存储/六库知识库/术语库
├── ui/  scripts/  tools/  fonts/  font_plugin/
└── tests/                 # 1900+ 测试
```
