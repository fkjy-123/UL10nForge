# 翻译质量保障系统实施计划

> 依据：《游戏汉化工具翻译质量保障系统》技术方案（2026-08-13，用户提供）
> 定位：把「翻译 + 知识 + 语境 + 检索 + 审核 + 修正 + 记忆」七环节闭环从方案落地为代码
> 对照基线：当前代码（v0.25.x，地毯式排查第九轮收官）

---

## 一、背景与核心理念

游戏汉化最大的难点不是「能不能翻译」，而是**在正确的游戏语境下，把原文准确、稳定、一致地翻译成中文**。传统「原文 → 翻译模型 → 中文」的单向链路处理不了：

- 多义词（Resume→简历/继续，Save→保存/救出/节省）
- 同一术语前后不一致、UI 文本当普通句子翻、占位符损坏
- 游戏专有语境无法长期积累

因此目标不是「用更多模型提高翻译质量」，而是**「让不同组件处理不同类型的问题」**：

| 组件 | 负责 |
|---|---|
| Hy-MT2-1.8B | 翻译（不负责最终质量判定） |
| Qwen3-Embedding-0.6B | 寻找相关知识（检索） |
| Qwen3-Reranker-0.6B | 判断候选是否真正匹配当前语境 |
| Qwen3-4B | 深度理解和审核语义 |
| 知识库 | 记住游戏世界 |
| 硬规则 | 保证机器可执行结构不被破坏 |
| 翻译记忆库 | 避免重复翻译、保持一致 |
| 自动重译 | 修复发现的问题 |

最终闭环：**检索 → 翻译 → 检查 → 筛选 → 深审 → 修正 → 记忆**。

---

## 二、目标架构

```
游戏原文（含上下文：场景/UI位置/前后文/文本类型）
      │
      ▼
知识检索层（Qwen3-Embedding-0.6B 向量检索）
  术语库 / 游戏语境库 / 特殊文本库 / 翻译记忆库 / 错误案例库
      │
      ▼
Hy-MT2-1.8B 主翻译
      │
      ▼
硬规则检查（占位符/标签/Rich Text/数字/键名——程序优先于 AI）
      │
      ▼
Qwen3-Reranker-0.6B 语境匹配（候选排序）
      │
      ▼
风险分流：低风险 → 通过 ｜ 可疑 → Qwen3-4B 深度审核
                              ├─ 通过 → 写库
                              ├─ 修正 → 再审核
                              └─ 重译 → 再审 → 通过
      │
      ▼
知识沉淀（术语库 + 语境库 + 翻译记忆库 + 错误案例库）
```

**双模式**：
- **轻量模式**（默认）：1.8B + 四库 + 硬规则 + Reranker-0.6B——只对真正可疑文本调 4B
- **高质量模式**：追加 Embedding + 向量库 + 4B 深审 + 自动重译 + 二次审核 + 知识沉淀

## 三、现状差距分析

### 已实现（当前系统）

| PDF 方案要求 | 现状 | 差距 |
|---|---|---|
| Hy-MT2-1.8B 主翻译 | ✅ `batch_translator.py` + llama.cpp 本地运行 | 无 |
| 术语库 | ✅ glossary.db + AgentMemory 词对（质量门门禁沉淀） | 无「禁止译法/词性/游戏专用含义/示例」字段 |
| 特殊文本库 | ✅ special_text.db + 六库 text 域（ui_text/dialogue/skill/equipment…） | 字段与 PDF 对齐度待检 |
| 翻译记忆库 | ✅ ProjectStore.memory（会话级）+ AgentMemory phrase（跨游戏） | 无 Embedding 相似检索（只有精确/子串命中） |
| 硬规则检查 | ✅ 质量门 20+ 确定性检查（占位符/标签/数字/键名/词对/格式模板） | 已超 PDF 要求（键名/词对防污染是排查实证产物） |
| 自动重译 | ✅ attempt 预算 + 失败原因分类 + 降级路径（native/knowledge 译例） | 反馈不是「审核结果描述」而是原因标签 |
| 知识沉淀 | ✅ AgentMemory 证据驱动晋升/退休 + 六库 learn | 语境记录无「正确含义/推荐译文/置信度」三元组 |
| 错误案例库 | ✅ knowledge.db fail_case 88+ 条（game/env/issue/root_cause/impact/fixed_version） | 缺「错误译文/正确译文/审核理由」字段 |
| 语义审核接口 | ✅ 强模型五维审核（术语/语境/专名/语义/风格）已建成（2026-08-12），runner `--no-review` 停用 | 审核结果二值化，未接风险分流 |

### 未实现（核心差距）

| PDF 方案要求 | 现状 | 差距等级 |
|---|---|---|
| **Qwen3-4B 深度审核 + 四级分级（PASS/MINOR/MAJOR/CRITICAL）** | 二值质量门 + 停用的强模型审核 | ★★★ 最高优先（质量保障的核心闭环） |
| **Reranker-0.6B 语境匹配** | 无 | ★★☆（语境检索的上游，可后置） |

## 四、分阶段实施计划

### 阶段 0：准备（1 周内）

**目标**：模型资产就绪 + 审核接入通道验证。

- [ ] 获取/量化 Qwen3-4B（Q4_K_M，~3GB）与 Qwen3-Reranker-0.6B（~1GB）GGUF
- [ ] 验证本地运行（llama.cpp 多模型加载，端口复用或双实例）
- [ ] 建立模型规格注册表（翻译/审核/重排三模型各自: 路径/ctx/并发/预算）

**验收**：`scripts/` 冒烟脚本可分别调用三模型输出确定结果。

---

### 阶段 1：深度审核 + 四级分级（对应 PDF 第三阶段，优先做）

**目标**：把「质量门二值判定」升级为「硬规则 + 深度审核分级」双闸门，MAJOR/CRITICAL 触发反馈式重译。

- [ ] **审核模型接入**：Qwen3-4B 独立服务端点 + 批处理（复用 reviewer 基础设施：批量配置/超时/并发实测记录）
- [ ] **四级审核输出**：PASS / MINOR / MAJOR / CRITICAL，附审核理由文本（审核项：语义一致性/否定/人物关系/条件/因果/数量/时间/语气/信息完整性——PDF §8 清单）
- [ ] **风险分流**：质量门通过 → 低风险直放；可疑（失败原因存在/术语冲突/长句/含否定词）→ 4B 审核；MINOR 记录不拦、MAJOR 修正、CRITICAL 重译
- [ ] **反馈式重译**：把「审核理由」注入重译 prompt（不是单纯重跑——PDF §13 Resume 案例：告诉模型「主菜单语境下 Resume 表示继续游戏不是简历」）
- [ ] **审核成本护栏**：只对可疑文本调 4B（实测目标：<15% 条目）；批量/预算/超时沿 reviewer 已验证配置
- [ ] 记忆门禁联动：MAJOR/CRITICAL 的译文不得进记忆；修正后译文优先沉淀

**验收**：抽查 200 条历史译文，CRITICAL 级错译（否定/人物关系颠倒）100% 被检出；正常译文 4B 调用率 <15%；重译后 MAJOR/CRITICAL 收敛率 ≥80%。

---

### 阶段 2：游戏语境库 + 多义词消歧（对应 PDF 第二/三阶段）

**目标**：Resume/Save/Charge 类多义词按「词义 + 语境」结构化解决。

- [ ] **语境记录扩展**：翻译条目上下文扩展为结构化语境（游戏/场景/UI位置/文本类型/前文/后文/相关文本/相关术语）——提取器已有 object/role 证据，补充场景归属（场景名/对象名）与相邻文本窗口
- [ ] **语境库表**：`context_entries`（原文 + 语境指纹 + 正确含义 + 推荐译文 + 置信度 + 来源）——知识库新增 domain 或独立表
- [ ] **语境命中链**：同游戏同语境精确命中 → 直填；跨游戏相似语境 → 注入 prompt 参考
- [ ] **多义词示例沉淀**：Resume 案例端到端（主菜单 6 项上下文 → 语境库命中 → 直填「继续」）做成验证用例
- [ ] 术语库字段升级：加「禁止译法/词性/游戏专用含义/使用示例」

**验收**：Resume/Save/Charge 三词在多游戏语境下 100% 正确消歧；语境命中率 ≥40%（现有短语记忆基线之上）。

---

### 阶段 3：Reranker-0.6B 语境匹配（对应 PDF 初版流程）

**目标**：候选语境排序——「哪些候选真正符合当前语境」。

- [ ] Reranker 服务接入（复用审核模型同套基础设施，0.6B 成本低可全量）
- [ ] 候选生成（Embedding 前先用启发式：词对精确/子串/同 object 同角色）
- [ ] 排序应用：Top-K 语境/记忆注入 prompt；低分候选不进 prompt
- [ ] 与质量门联动：Reranker 高分但质量门失败 → 该词对/语境标记存疑（防污染记忆）

**验收**：Reranker 对 Resume 类样本选「继续」为最高分；prompt 注入量不增（Top-3 封顶）。

---

### 阶段 4：Embedding 向量检索（完整版，对应 PDF 第四阶段）

**目标**：统一知识检索层——相似文本去重、历史翻译检索、相似案例召回。

- [ ] Qwen3-Embedding-0.6B 接入 + 向量库（sqlite-vec 或 faiss，本地优先）
- [ ] 索引对象：术语/语境/历史翻译/游戏文本/错误案例全向量化
- [ ] 相似去重：同游戏出现数百次的 "Are you sure?" 首译后直接复用（预算大省）
- [ ] 相似案例召回：Save the game. → 召回 Load the game./Save Game./Saving... 帮模型理解系统语境
- [ ] 翻译记忆增强：向量命中 → 直接给 Hy-MT2 参考译文

**验收**：重复文本零重复翻译；相似案例召回 Precision@5 ≥0.8（人工标注 100 条评估集）。

---

### 阶段 5：自动学习 + 错误案例闭环（对应 PDF 第五阶段）

**目标**：错误案例驱动 Prompt/规则/术语库自动优化，为微调积累数据。

- [ ] 错误案例结构化升级：fail_case 补「错误译文/正确译文/错误类型/审核理由」字段 + 迁移存量
- [ ] 错误类型统计哨兵：MAJOR/CRITICAL 按类型聚合（语义/否定/关系/术语/结构）——驱动规则与 Prompt 优化方向
- [ ] 规则自动建议（人工确认）：高频错误类型 → 生成硬规则候选（沿用排查 SOP 的「形态清单化」）
- [ ] 微调数据导出：确认过的（原文/上下文/译文/审核通过）对导出训练集（为专用小模型准备）

**验收**：连续 3 个游戏错误率趋势下降；规则候选采纳率 ≥50%（人工确认）。

## 五、优先级与资源建议

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 阶段 1 深度审核四级分级 | 质量保障核心闭环；语义错译（PRRESS→「媒体」类）是当前质量门唯一能力边界 |
| P0 | 阶段 2 游戏语境库 | 多义词是 PDF 全文反复强调的核心痛点；与阶段 1 共用上下文采集 |
| P1 | 阶段 3 Reranker | 初版流程要求；0.6B 成本低 |
| P1 | 阶段 4 Embedding | 完整版核心；去重收益直接（重复文本常见） |
| P2 | 阶段 5 自动学习 | 需要前四阶段的数据积累 |

**模型预算**（本地 GGUF，llama.cpp）：
- Qwen3-4B Q4_K_M ~3GB（审核，只跑可疑批次）
- Qwen3-Reranker-0.6B ~1GB（语境排序）
- Qwen3-Embedding-0.6B ~1GB（检索，可最后再加）

## 六、风险与边界

1. **审核模型成本**：4B 全量审核不可接受——风险分流阈值（15% 调用率）是硬约束，用「质量门失败/长句/否定词/术语冲突」启发式挑可疑
2. **审核模型自身误判**：4B 也可能错——审核结果过「硬规则复查」；MINOR 不拦（防止过度修正）
3. **语境指纹可靠性**：场景归属依赖提取器（object/role 证据）——语境不完整时降级为无语境匹配，不阻塞
4. **本地部署约束**：0.6B~4B 级别——符合 PDF「尽量用 0.6B~4B 解决绝大部分任务」，不用大模型
5. **免实测/免云端审核流程**（现行用户指令）——阶段 1 的 4B 审核是本地模型，不冲突；云端语义审核维持停用

---

## 七、落地节奏建议

- **第 1 周**：阶段 0 准备 + 阶段 1 的 4B 接入与四级输出
- **第 2~3 周**：阶段 1 风险分流 + 反馈式重译 + 记忆联动（首个游戏闭环验证）
- **第 4 周**：阶段 2 语境库（与地毯式排查第 10 轮并行——语境采集随排查自然发生）
- **第 5~6 周**：阶段 3 Reranker + 阶段 4 Embedding（完整版闭环）
- **第 7 周起**：阶段 5 自动学习（数据积累后启动）

每个阶段完成后跑 2 个新游戏验证（沿用双游戏并行排查闭环，0 失败或收敛为验收基准）。
