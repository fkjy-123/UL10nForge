# 写回后实机测试计划（翻译质量闭环的最后一环）

> 2026-08-12 制定。背景：写回后游戏内问题很难发现、记录很难找到
> （用户实证）。本计划是每款已闭环游戏的**强制实机验证清单**——
> 写回验证只保证二进制完整（重开验证），游戏内是否正常显示/运行
> 需要按本计划实测。测试结果写入 final report，问题按 §4 定位修复。

## 0 测试前提与产出

- 前置：游戏已写回成功（container/object PASS、revert 0）、汉化输出
  目录仍在（未删，测试完成确认无问题后才删）
- 产出：
  - `docs/all record/<slug>/final report/` 中「实机测试」章节（逐项结果）
  - 发现的问题 → 写回定位 → 修复 → 记录 fix record
- 测试环境：Windows 11 + 游戏原版目录（D:\游戏\<slug>）

## 1 启动与稳定性（优先级最高）

| # | 测试项 | 方法 | 发现问题的定位方向 |
|---|---|---|---|
| 1.1 | 游戏能启动 | 双击 exe，等待进入主菜单 | 不启动 → 检查启动日志（Unity Log / BepInEx Log）、崩溃转储；若 boot.config 被改（F14 教训：legacy→「遗产」）→ 比对原版配置文件 |
| 1.2 | 无启动崩溃 | 启动后 3 分钟内无闪退 | 闪退 → CrashReport 目录、Windows 事件查看器；文本写入崩溃 = 长度头/字符串表破坏（F15 教训） |
| 1.3 | 长期稳定 | 连续运行 15 分钟（含过场动画/切换场景） | 中途崩溃 → 对应场景的文本（容量截断/格式串破坏） |
| 1.4 | 存档/读档 | 新建存档 → 退出 → 重新进入 → 读档 | 存档异常 → 存档文件格式被翻译破坏（日期/数值格式串——F14 同类） |

## 2 中文显示（字体与文本渲染）

| # | 测试项 | 方法 | 定位方向 |
|---|---|---|---|
| 2.1 | 中文字体生效 | 主菜单/对话框观察：无方块（□）、无乱码 | 方块 → 字体未命中（font-health.json 状态：runtime_verified / payload_deployed）→ 按字体层级排障 |
| 2.2 | 关键 UI 全覆盖 | 逐屏检查：主菜单、设置、存档界面、暂停菜单 | 英文残留 → 该文本未翻译/未写回（查 translated.txt 该条状态） |
| 2.3 | 文本不截断 | 长文本（物品描述、对话长句）完整显示 | 截断/溢出 → 该条译文长度超容量被截断（写回日志 truncated 记录）→ 缩短译文重译 |
| 2.4 | 无字符缺失 | 特殊字符（…、「」、·、①）正常 | 缺失/变形 → 字体缺字形 → 换字体或补字形 |
| 2.5 | 变量/占位符保留 | 含 {0}、%s、<b></b> 等格式的文本显示正常 | 显示异常（如 {0} 变成 0）→ 占位符被改（检查译文占位符完整性） |

## 3 核心功能可达性（写回破坏的重点区）

| # | 测试项 | 方法 | 定位方向 |
|---|---|---|---|
| 3.1 | 核心玩法可达 | 新游戏 → 完成首个可玩关卡/流程 | 卡死/报错 → 该处文本写入破坏逻辑（字符串匹配——F21 教训：xinput/正则串翻译破坏输入映射） |
| 3.2 | 菜单导航 | 各菜单逐项点击，返回路径完整 | 按钮无响应 → 按钮文本被译（真按钮判定错误）→ revert 或修正判定 |
| 3.3 | 对话框推进 | 对话文本逐句推进不卡住 | 对话卡住 → 文本换行/换行符丢失（newline_mismatch 类） |
| 3.4 | 输入绑定 | 键盘/手柄操作正常（移动/交互/暂停） | 按键无响应 → 输入映射文本被译（F14/F21 教训）→ 结构跳过规则补充 |
| 3.5 | 设置保存 | 修改设置 → 退出 → 重进验证保留 | 设置不保存 → 配置值被翻译（boot.config 类） |

|---|---|---|---|

| 4.5 | 歌词/长段落 | 歌词类文本完整显示 | deadbeat：歌词超长截断/续写回显 |

## 6 问题处置流程（发现问题后）

1. **定位**：按上表「定位方向」列找到根因类型（文本破坏/字体/判定误杀）
2. **根因**：对照 `text/failed.txt`、`review/review-report.md`、写回日志
   确认是该文本的判定问题还是写回问题
3. **修复**：按「系统性通用规则」修（禁止单游戏特判），回归测试全绿
4. **重写**：修复后重跑该游戏（原版重来）验证问题消失
5. **记录**：问题 + 根因 + 修复 → fix record；测试结果 → final report

## 7 执行方式

- 每款已闭环游戏执行本计划（1-4 章逐项），结果写入 final report
  实机测试章节
- 游戏无法启动（缺运行库等环境问题）→ 记录环境原因，不阻塞闭环
- 测试中发现的问题按 §6 处置后重跑闭环

## 8 计划自身的持续优化

- 每款游戏实测发现的新问题形态 → 补充到本计划相应章节
- 多次零问题的测试项 → 标记为可跳过项（成熟验证）
- 测试自动化：后续考虑脚本化启动/截图/日志采集（当前手动+证据留存）
