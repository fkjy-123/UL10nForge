# 识别模块升级计划（覆盖率 ≥95%）

目标：把「文本识别/提取」模块从当前状态升级到真实 Unity 游戏文本
**位置覆盖 ≥95%** —— 游戏里的每一处可翻译文本都应被发现、分类、
可提取。所有验证只跑副本，绝不打开游戏窗口、不启动 exe。

---

## 阶段 0：基线度量（升级前先摸清家底）

- 在 `D:\游戏` 全量跑当前 scanner（只读），产出每个游戏的：
  文件格式分布、条目数、来源分类（text/unity/mono/il2cpp）
- 建立**覆盖率度量**：识别覆盖率 = 发现的文本位置数 ÷ 估计文本位置
  总数。总数用三路交叉估计：①按扩展名/容器类型清点所有「可能含
  文本」的文件；②字节级抽样扫描找漏网文本（非 UTF-8 编码、无扩展
  名文件、AssetBundle 内嵌）；③与文献资料中的已知位置类型比对
- 产出：`docs/基线覆盖率报告.md`（升级前快照，作为升级后对照）

## 阶段 1：Web 文献研究 → 资料大全

主题（每主题多来源）：
1. Unity 文本载体总览：UGUI Text / TextMeshPro / TextMesh、TextAsset、
   ScriptableObject、Localization（内置 + 三方）、.resx、csv/json/xml/
   yaml/sqlite/po、硬编码字符串
2. 二进制文本位置：Mono #US 堆、IL2CPP global-metadata 字符串表、
   .resS/.resource 外部数据、AssetBundle 内嵌 SerializedFile、
   Addressables（catalog + bundle 组）、shader/audio 内嵌字符串
3. 提取工具与方法：UnityPy、AssetStudio、UABE/AssetRipper、
   Il2CppDumper、dnfile、ged2json 等，各自的适用性与局限
4. 编码与混淆：UTF-8/UTF-16/BOM/GBK、TextMeshPro 富文本标签、
   StringLiteral 混淆、加密文本（XOR/Base64）
- 产出：`docs/Unity文本识别与提取资料大全.md`（含来源链接、按位置
  类型组织、每类附提取方法与优先级）

## 阶段 2：100+ 游戏深度调查

对 `D:\游戏` 全部游戏（当前 111 个）逐个深度调查，多方法交叉：
- **A. 文件系统普查**：扩展名分布、命名模式（localization/language/
  strings/text/ui/i18n/lang）、无扩展名文件、非 UTF-8 编码探测
- **B. Unity 容器解析**：UnityPy 全量 load，列 SerializedFile、
  AssetBundle（含嵌套）、TextAsset/TextMeshPro/MonoBehaviour 清单
- **C. 字节级盲扫**：对非容器文件做 UTF-8/UTF-16-LE/GBK 解码 + 英文
  可读串统计，找「格式外的文本」
- **D. IL2CPP/mono 字符串表**：Il2CppDumper / dnfile 提取全局字符串，
  评估可翻译性（只收 display 角色）
- 产出：每游戏一份 JSON 指纹 + `docs/文本识别全覆盖调查报告.md`
  （汇总：所有文本位置类型、每种类型的发现率、当前工具的覆盖缺口
  ——缺口的优先级即阶段 3 的升级清单）

## 阶段 3：识别模块大升级（核心）

按调查报告的缺口优先级实现，预期改造：
1. **新格式适配**：调查发现的前 N 个未覆盖/半覆盖格式
2. **AssetBundle 递归解包**：嵌套 bundle、bundle 内 TextAsset 等
3. **外部数据解析**：.resS/.resource 的字符串堆
4. **泛化文本启发式**：字节盲扫 + 语言检测 + 噪声过滤，作为
   「无格式可依」文本的兜底（纳入过滤与分类，防误翻）
5. **IL2CPP 补充**：global-metadata 字符串表 display 角色判定
6. **编码探测增强**：UTF-16 BOM、GBK、Shift-JIS 等探测
7. **覆盖率回归**：升级后在 `D:\游戏` 重跑，覆盖率 ≥95% 目标，
   与阶段 0 基线对比，报告提升

每步配单元测试 + 全量回归（当前 1315 用例基线）。

## 阶段 4：itch.io 外部测试
