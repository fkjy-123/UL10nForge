## 3. 任务一：核心功能升级（按实施计划，最高优先）

严格按 `docs/翻译质量保障系统实施计划.md` 推进，**按阶段顺序**，每个阶段完成并验收后才进下一阶段。

### 3.1 阶段 0：模型接入 + 硬件智能分配（先完成）

1. 新建 `hanhua/core/model_registry.py`：ModelSpec（name/path/kind(translate|review|rerank|embed)/backend/gpu_layers/ctx/keep_alive/max_concurrency/budget），注册四模型
2. 新建 `hanhua/core/hardware_planner.py`：探测 GPU 显存/系统内存 → 输出四模型分配方案：
   - **0.6B×2（rerank/embed）恒为 CPU**（毫秒级任务，占 GPU 无收益）
   - **4B 审核 / 1.8B 翻译按用户硬件自动分配**：
     - 无 GPU → 全 CPU；4~6GB → 4B GPU 按需 + 1.8B CPU；6~8GB → 4B 常驻 + 1.8B 按需；≥8GB → 全常驻
   - 依据 `vram.py` 显存预估 ≤ 可用显存 90% 才上 GPU；GPU 加载失败自动回退 CPU（复用 `local_model.py` 现有 cuda_missing 回退链）
   - 常驻/按需用 llama.cpp `--keep-alive`；显存紧张时 4B 降 `--ctx-size 4096` / `--parallel 1`
3. 四模型各真实冒烟一次（记录输出），审核成本基线（100 条耗时记录）
4. 验收：六档硬件（无 GPU/4/6/8/12GB/低内存）模拟均得出可运行方案；回退路径正确；0.6B×2 恒为 CPU

### 3.2 阶段 1：深度审核闭环（P0，务必完整）

按实施计划 T1-1~T1-8 完整实现：
- 审核 prompt 四级化（JSON：level PASS/MINOR/MAJOR/CRITICAL + reason + issues，复用 `_parse_verdict` 模式）
- `ReviewResult` 扩展 level 字段 + `apply_verdict` 分发（PASS 写库 / MINOR 记录放行 / MAJOR 修正 / CRITICAL 重译）
- 风险分流器 `risk_gate.py`（按 §4.2 决策表，4B 调用率 <15% 硬约束）
- 反馈式重译（审核理由注入重译 prompt，共享失败预算防死循环）
- 再审收敛（上限 2 轮；仍 CRITICAL 保留原文 + blocked + 写错误案例）
- 记忆门禁（MAJOR/CRITICAL 不进记忆；PASS 优先进记忆）
- 审核日志报告
- 测试 `tests/test_review_levels.py`（四级判定解析、分流全分支、反馈重译注入、记忆门禁、收敛上限）

### 3.3 阶段 2~4：语境库 / Reranker / Embedding（尽量完整）

按实施计划推进（语境库 context_entries → Reranker 接入 → Embedding 向量检索 + sqlite-vec 或等价零依赖方案）。**每个阶段以测试全绿为完成线**，时间不够就停在完整阶段处，绝不做半截任务。

### 3.4 移除云端审核（必做，独立小任务）

1. 定位审核链路中走在线 API 的云端分支（reviewer.py 等审核调用处的 provider/后端选择逻辑），**删除云端审核实现**——审核统一走本地 Qwen3.5-4B，不存在云端审核路径

## 6. 任务四：知识库批量丰富（联网搜集）

**目标：不一个个游戏慢慢攒，通过联网搜集批量丰富知识库六库内容。**

### 6.1 搜集方向（每方向实际搜索，来源可追溯）

1. **游戏本地化规范/行业惯例**：专有名词处理、UI 短词、占位符/变量、标点规范、长度约束、快捷键键名（RMB/LMB/SPACE 等）的中文标准通称

3. **常见游戏专名/系列词**：通用性强的游戏术语（Lore/Quest/NG+/Co-op 等）与行业统一译法
4. **Unity/引擎技术文本**：引擎调试串、日志模板、UGUI/TMP/UI Toolkit 相关文本形态的识别与处理惯例
5. **中文游戏本地化译法资源**：社区/公开文档中的常见误译清单、多义词（Resume/Save/Charge）各语境译法

### 6.2 入库规则（防污染，历史教训）

- 所有批量内容**必须带来源链接**（来源字段），置信度标记为「社区/网络参考」
- **批量内容只入「参考知识」层**（knowledge.db 的 text/quality/unity_structure 等 domain 的参考条目），**绝不自动成为 glossary.db 强制词对**
- 语境敏感的词对（方向/设备/动词等）禁止单字词对全局强制；组合词对才可候选强制
- 入库后跑查询测试验证可检索

### 6.3 验收

- 每库新增参考条目（数量汇报）；来源链接完整；检索测试通过；无强制词对污染
