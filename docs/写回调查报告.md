# 写回模块调查报告(对照审计)

> 日期:2026-08-09。前置文档:`docs/写回资料大全.md`(4 路网络文献 170+ 条 + 代码摸底)。
> 本文把「文献结论」逐一对照「当前代码实现」,给出已覆盖/部分/缺口三级判定,输出修复清单。

## 0. 审计方法

1. 通读写回全链路代码(project.py `write_all` → writer.py / unity/writer.py / unity/mono_dll.py / unity/il2cpp.py / unity/font_replace.py / formats/*)。
2. 将 4 路文献(SerializedFile/AssetBundle、UI 交互社区实证、Mono/IL2CPP、TextAsset 编码与内容)的风险点映射到代码路径。
3. 每个风险点判定:✅ 已覆盖 / ⚠️ 部分覆盖(有差距)/ ❌ 缺口 / ➖ 不适用或不可修(需报告提示)。
4. 关键结论用真实数据验证(9+ 个 global-metadata.dat、真实游戏写回闭环)。

## 2. 修复清单(按优先级)

### P0(必须修,已实证)

- **F1-IL2CPP explicit**:`_patch_metadata` 更新记录区 `<length>` 字段为译文实际字节数(v24/27/29/31)。
- **F1-IL2CPP implicit**:v39 无长度字段,收缩后流式重建数据区+链式更新全部 dataIndex(保持 data_size 与 header 不变,尾部留空洞)。
- **F1-#US**:`_patch_dll` 同时更新压缩长度前缀(值=译文字节+1)、数据、flag(flag 移到新数据末尾之后);前缀 size class 变小可行(原位覆盖,残字节被新数据覆盖)。
- **F1 验证**:重开验证改为「重新 parse 池 → 记录 length/前缀 == 译文实际字节数」,替代 rstrip 比较——补齐 F6 闭环盲区。
- **F1 变体(真实闭环新发现)**:`parse_string_literals` 的 valid 过滤(空长度/非 UTF-8 记录)破坏「记录序号 ↔ 记录区位置」对应——
  - explicit(cosl 实证):按 valid 序号写记录区 → length 字段写错条目 → 重开区间重叠 → 解析整体拒绝;
  - implicit(minato 实证):重建只重写 valid 条目 → 被过滤条目残留旧 dataIndex,dataSize 缩小后越界(末 2 条 528463/528466 > 新 dataSize)→ 重开解析拒绝。
  - 修复:explicit 按 data_index 映射记录区位置(同一 data_index 多条记录只更新 length>0 的实际条目,空记录保持 0 不新增区间重叠);implicit 全部记录(含被过滤的空/非 UTF-8)参与紧凑重建,数据原样搬运,记录区全部条目链式更新。
- **F1 变体(自动化加固追加)**:
  - 同源盲区消除:提取/重开验证与 parse 共用同一套解析,系统性误解会自证失效——新增 `_independent_pool_records` 第二套独立读取器(不同代码路径硬读记录区,不做重叠防御/过滤),`_cross_validate_pool` 在写回前交叉核对「parse valid 子集 == 独立读取器过滤后子集」,不一致拒绝补丁;
  - 差异白名单:`_assert_diff_whitelist` 对 patch 前后逐字节 diff——explicit 只允许「被改记录数据段 + 记录区 length 字段」差异,implicit 只允许「数据区(含空洞清零) + dataSize 字段 + 记录区全部条目」差异,header 其他字段与其他区段(方法名表/类表等游戏逻辑所在)零字节被碰,任何越界字节变动 → ValueError 拒绝;
  - 占位符全量校验:占位符 `{n}` 完整性从「截断路径」扩展到所有写回条目(译文缺失原文占位符即拒绝,不依赖翻译阶段质量门)。
- **F2**:截断后重新验证 `{0}`/`{n}` 占位符完整性;被破坏则拒绝写回该条(报告 rejected)而非产出坏字符串。

### P1(影响真实游戏,修复)

- **F3**:TextAsset 写回侧 strict decode(译文/原文必须能 strict UTF-8 编解码,否则拒绝);提取侧过滤加「strict decode 验证」,从源头排除 mojibake。
- **F4**:typeless 文件优先 rawstr 字节级补丁;typetree 缺失时禁止 save_typetree;read 异常 → 整文件跳过写回。
- **F7**:XML 写回避免重序列化破坏——方案:仅当译文与原文等长安全替换文本节点;或检测 CDATA/DOCTYPE 存在时退回「字节级替换」(等长或短于原文本时原位覆盖)。至少:检测到 CDATA/DOCTYPE 时报告警示。
- **F2 变体(新)**:省略号「…」可能不在游戏字体字形表 → 截断提示符改用 ASCII "…" 替代或可配置。

### P2(防御加固)

- **F5**:非 Addressables CRC 引用 → 发布报告警示字段。
- **CSV EOL**:写回保留原始行终止符(CRLF 文件写回 CRLF)。
- **BOM 复核**:CSV/TextAsset 写回后 BOM 与原文件一致;提取时 `read_text` 的 BOM 行为统一。
- **INI 复核**:确认 ';'/'#'/引号写回策略与提取侧一致。
- **报告提示项**:逻辑键、culture 比较、反作弊、硬编码字符串、动态字体——写入发布报告「已知边界」章节。
