## 2. 关键发现（本轮实证）

1. **Addressables catalog.bin 不是 SerializedFile**：头部 kMagic `0x0DE38942` 是 `BinaryStorageBuffer` 的 `ResourceLocator.Header`（`string.GetHashCode`，平台不稳定）。大端头自洽判定（v22 48 字节布局：metadata/file_size/version/data_offset 全大端）将其 version 读为 `0x24000000` 而拒绝 → binary 分支。catalog 只含路径/GUID/CRC 键无文本，Addressables 管线用字节级 CRC 替换，无需解析。
2. **Unity 6000（v22）MonoBehaviour typetree 在 UnityPy 1.25.3 下 264/268 失败**（`Expected to read 52 bytes, but only read 32`），1.25.3 已是 PyPI 最新版。兜底：raw scan 全权接管分类，SEWER CALL 场景 UI 文本完整采到（FULLSCREEN/NEW GAME/SENSITIVITY…）。
3. **老版 IL2CPP（v24/v29）字面量池是引擎噪音池**：minato 16,541 条可解码字面量中 0 条真实游戏文本（游戏文本在资源里），全是引擎异常消息/属性名/系统库字符表。本轮过滤（格式占位符 2,328 条、前导空白调试、字符表、短串）+ 分类（交互提示→display/medium；句子→display/low 留档；其余 structural），可翻译噪音从 7,806 → **0**。
4. **Mono 嵌入资源在 15 游戏样本 0 命中** → 优先级低，暂不实现 dnfile ManifestResource 解析。

## 3. 回归与测试

- 全量 `pytest tests/`：**1242 passed, 27 skipped，0 失败**（提交前 1238，本轮新增 4：serialized 大端判定 accept/reject、引擎内置资源黑名单、il2cpp 过滤分类）

- 真实游戏全量提取（15 游戏）：asset 提取 0 错误；DLL/metadata 提取 0 错误

## 4. 已知限制与后续

- Unity 6000 typetree：UnityPy 库限制（不可自行修复），raw scan 兜底已覆盖；若 UnityPy 修复 typetree，全叶子分类器自动接管
- IL2CPP v39（Unity 6）无样本：过滤规则对 v39 安全（强证据才可翻译），但 display/low 留档量待真实样本校准
- 运行时动态拼接/网络下发/加密文本：静态提取无法覆盖，靠「全资源收录 + 低置信留档」兜底（DB 不丢任何候选）
- 嵌入资源：15 游戏 0 命中，如遇真实需求再加 ManifestResource 解析
