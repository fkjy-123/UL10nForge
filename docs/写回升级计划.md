# 写回模块升级计划(2026-08-09)

> 前置:`docs/写回资料大全.md`(文献)、`docs/写回调查报告.md`(对照审计)。
> 目标:写回绝不产出「运行时坏字符串」——硬性要求。执行顺序按依赖,每步带验证。

## 阶段一:P0 尾部 NUL 修复(核心)

### 1.1 il2cpp.py:新增池补丁纯函数

新增 `patch_metadata_strings(raw: bytes, changes: dict[int, bytes]) -> bytes`:

- 解析 header 拿 (lit_off, lit_table_size, data_off, data_size, entry_size, record_mode)(复用 `_LAYOUTS`)。
- **explicit(v24/27/29/31)**:对每条变更(data_index → 新 UTF-8 字节):
  - 校验新字节数 ≤ 原 length(防御:超长抛 ValueError);
  - 数据区原位写 payload(剩余空间保持原字节,不产生任何布局变化);
  - 记录区 `<length>` 字段 = 新字节数。
- **implicit(v39)**:无长度字段,收缩传播:
  - 按原顺序流式重建数据区:每条记录前拷贝「间隙」原内容 → 写新 payload(未写条目原样拷贝)→ cursor 推进;
  - 所有记录 dataIndex 写入新位置;
  - data_size / header / 其他区一律不动(尾部空洞保留)。
- 返回补丁后的完整字节;任何校验失败抛异常(整文件不落盘)。

### 1.2 writer.py:_patch_metadata 重构

- 用 `il2cpp.parse_string_literals` 重建布局信息(data_off),entry meta.file_offset → data_index。
- `_fit_bytes` 增加 `pad: bool = True` 参数;metadata 路径传 `pad=False`(不填 NUL,直接给实际字节)。
- 收集 changes → `patch_metadata_strings` → `_atomic_write_bytes`。
- **重开验证升级**:重新 `parse_string_literals(reopened)` → 每条:记录 length(显式)或下一条差值(隐式)== 新 payload 长度,且数据字节 == 新 payload;不一致抛 ValueError。

### 1.3 writer.py:_patch_dll(#US 侧)重构

- 新前缀值 `ln = 新字节数 + 1`,按 ECMA-335 压缩编码(1/2/4 字节)写回;
- 新数据起点 = heap_offset + 新前缀宽,写译文字节;flag 写到新数据末尾之后(原 flag_offset 逻辑废弃);
- 旧前缀残字节自动被新数据覆盖(前缀变窄时),无需清理;
- 前缀宽变大不可能(译文 ≤ 原文);防御校验。
- 重开验证:重新 `_walk_us_heap_records` → 该记录 value == 译文,flag 正确。

### 1.4 单元测试

- 合成 IL2CPP metadata(显式 8 字节记录 + 隐式 4 字节记录各一):小数据区、紧凑布局、真实 magic/header 字段,构造严格符合解析器预期;
- 断言:写回后运行时读取(按记录长度)无尾部 NUL;重开验证通过;
- v39 链式:3 条字符串,缩短第 1 条,断言后续 dataIndex 前移且各自内容正确;
- #US:短译文 + 长原文(前缀 2 字节 → 1 字节),断言 prefix/data/flag 三处正确;
- 用 9 个真实 metadata 文件跑全量写回+重开验证(探针脚本升级为回归测试)。

## 风险与边界

- v39 流式重建会改动全部 dataIndex——只对「确实有写回条目」的 metadata 执行;无条目时 `patch_metadata_strings` 直接返回原字节(零改动)。
- #US 前缀变窄后,我们自己的 `_walk_us_heap_records` 流式遍历仍正确(每条记录自洽);游戏侧按 token 偏移定位,不受影响。
- 不引入任何布局变化:数据区总大小、记录数、header、流头全部保持不变。
