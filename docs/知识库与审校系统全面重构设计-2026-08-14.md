## 2. 当前存在的问题（审计结论）

| # | 问题 | 影响 | 定位 |
|---|---|---|---|
| P1 | knowledge_items 无置信度/状态/优先级 | 无法区分人工确认与 AI 生成；无生命周期 | knowledge.py `init_schema` |

## 3. 新旧架构对比

```
旧：  Text → [规则质量门] → [risk_gate 决策表送审] → [LLM 二元好坏] → PASS/FAIL
新：  Text → 分类 → 多路召回(精确/归一化/关键词/语义/语境/TM) → 重排
        → Context Builder(优先级+去重+冲突检测+预算) → 翻译
        → 双层审校(Rule Engine 确定性 + LLM 十维语义) → Review Fusion
        → Risk Engine(0-100 评分) → 自动分流(PASS/REVIEW/BLOCK)
        → 反馈学习(错误→Error Pattern 候选) → 知识库(生命周期管理)
```

不变原则（指令 §21 工程原则，全程遵守）：
- 确定性规则优先，LLM 只处理语义问题（已有 quality.py 基础，不重写）
- 不破坏现有汉化流程；增量、可验证、可回滚
- 模型可替换（model_registry.py 已有注册机制，不动）

## 4. 数据模型设计

### 4.1 knowledge_items 扩展（P1/P3）——SQLite 加列，兼容旧数据

```sql
ALTER TABLE knowledge_items ADD COLUMN confidence REAL DEFAULT 0.6;
ALTER TABLE knowledge_items ADD COLUMN status TEXT DEFAULT 'verified';
   -- candidate / verified / locked / deprecated（指令 §17-18 生命周期）
ALTER TABLE knowledge_items ADD COLUMN priority INTEGER DEFAULT 0;
   -- 0-10，游戏专属 > 锁定术语 > 语境 > 实体 > TM > 错误模式 > 通用规则
ALTER TABLE knowledge_items ADD COLUMN source TEXT DEFAULT 'ai';
   -- manual / official / imported / ai / human_corrected / review_confirmed
ALTER TABLE knowledge_items ADD COLUMN source_ref TEXT DEFAULT '';
   -- 来源文本/文件/游戏/时间（可追溯）
ALTER TABLE knowledge_items ADD COLUMN usage_count INTEGER DEFAULT 0;
ALTER TABLE knowledge_items ADD COLUMN success_count INTEGER DEFAULT 0;
ALTER TABLE knowledge_items ADD COLUMN updated_at TEXT;
```

置信度基准（指令 §7）：人工确认 1.0 / 官方文本 1.0 / 人工修改 0.95 /
审核通过 0.85 / AI 自动生成 0.60。

### 4.2 error_patterns 新表（P4）

```sql
CREATE TABLE IF NOT EXISTS error_patterns (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  original TEXT NOT NULL,
  wrong TEXT,                -- 历史错误译文（可空：仅 wrong 语法）
  correct TEXT NOT NULL,
  context TEXT DEFAULT '',   -- 场景（Pause Menu / Combat …）
  game TEXT DEFAULT '',      -- 来源游戏
  confidence REAL DEFAULT 0.85,   -- 人工纠正沉淀 = 0.95+，AI 提取 = 0.6
  status TEXT DEFAULT 'candidate', -- candidate/verified/deprecated
  usage_count INTEGER DEFAULT 0,
  created_at TEXT, updated_at TEXT,
  UNIQUE(original, wrong, correct, context)
);
```

写入门禁（指令 §17 不污染原则）：只有 **人工纠正**（manual_correction.py
链路）与 **审校确认**（review_confirmed）直接落 verified；模型自生成
只进 candidate。

### 4.3 TM 模糊匹配（P5）——不改表，memory.py 加查询层

- 精确（已有 MD5）→ 归一化（去空格/大小写/标点，MD5' 命中）→
  前缀/包含相似（token 级）→ 置信折算：精确 1.0 / 归一化 0.95 /
  相似 0.7×相似度。检索结果带来源回溯。

### 4.4 risk 评分（P6）——风险分数入 meta，表结构不动

`risk_score: 0-100` 存条目 meta（或审校记录表），等级映射：
CRITICAL ≥85（禁写回）/ HIGH ≥60（人工）/ MEDIUM ≥35（本地模型二次）
/ LOW <35（自动通过）。五档信号加权（见 §8）。

### 4.5 review_report 持久化（P8）——record_writer 加审校字段

writeback 记录行扩展：`审校：overall=92 decision=PASS risk=12 证据数=4`
（append-only，旧行不迁移）。

## 6. 检索流程（新）

```
文本 → 分类(role/kind/domain)
 → Exact(glossary + TM)          # 精确词对/记忆
 → Normalized(TM 归一化)          # 去空格大小写标点
 → Keyword(知识库 search_keyword)
 → Semantic(VectorStore 四路召回 + rerank)   # 已有
 → Context(ContextStore 指纹消歧)            # 已有
 → Error Pattern(按 original/context 命中)   # 新增
 → 规则过滤(priority 0 且 status!=verified 且低置信 → 降权)
 → 去重(同 pattern 多路命中合一)
 → 冲突检测(同 original 多译文 → 取最高优先级 + 记 conflict 标志)
 → 优先级排序(§4.1 优先级链)
 → Context Budget(总 token 上限，超出截断最低优先级)
 → 最终模型上下文
```

## 7. 审校流程（新）

```
译文 → [Rule Engine: quality.py 全规则]      # 确定性，已有，不动
      → 规则错误命中？→ 修复建议 + risk 加分
      → [LLM 十维审校]（指令 §10）：
          语义准确 / 游戏语境 / 术语一致 / 自然度 / 风格 /
          完整性 / 幻觉 / 结构完整 / 歧义 / 机翻痕迹
      → 结构化 JSON（overall_score + decision + 维度分 + issue + reason）
      → Review Fusion（规则 + LLM 融合：规则硬错 → 直接 FAIL 不覆盖）
      → Risk Engine（§8 评分）→ 分流：
          LOW → 自动通过
          MEDIUM → 二次审校（_retranslate_with_feedback，已有）
          HIGH → 人工确认池
          CRITICAL → 禁写回
      → 反馈学习（用户纠正 → error_patterns 候选 + TM 沉淀）
```

## 8. 风险评分方案

`risk_score = Σ(信号分值 × 权重)` 截断 0-100，未命中任何信号 = 基础 12 分
（低基线）：

| 信号 | 分值 | 权重 | 说明 |
|---|---|---|---|
| 规则硬错（quality failed） | 55 | ×1.0 | 确定性错误最高优先 |
| 术语冲突（glossary_mismatch） | 40 | ×1.0 | 硬冲突 |
| 多义词无语境证据 | 30 | ×1.0 | 语境证据支持 → −25（消歧完成） |
| 历史错误模式命中 | 25 | ×(模式置信) | Error Pattern 命中即警示 |
| 长文本（token>60） | 15 | ×1.0 | 信息丢失风险 |
| 否定/条件 | 15 | ×1.0 | 语义反转 |
| 角色/专名文本 | 10 | ×1.0 | 术语一致性风险 |
| Embedding 低相似（<0.6） | 20 | ×1.0 | 与历史记忆差异 |
| 与 TM 记忆差异 | 15 | ×1.0 | 同原文历史译文不同 |
| LLM 审校分 <70 | 30 | ×(70-score)/10 | 模型意见 |
| LLM 审校分 <85 且自然度维度 issue | 10 | ×1.0 | 机翻痕迹 |

等级映射：CRITICAL ≥85（禁写回）/ HIGH ≥60（人工）/ MEDIUM ≥35（二次审校）/
LOW <35（自动通过）。max(规则硬错) 强制 CRITICAL/HIGH 不降级
（mandatory 语义保留——不破坏现有 mandatory 强制通道）。

## 9. 数据迁移方案

- **knowledge_items**：`ALTER TABLE ... ADD COLUMN` 全带 DEFAULT——
  旧行自动获得 confidence=0.6（AI 生成保守值）、status='verified'、
  priority=0、source='ai'。零迁移脚本，重开库即生效；`init_schema` 幂等
  （IF NOT EXISTS / 列存在检查）。
- **TM/语境/记忆**：表结构不动，只加查询层。
- **error_patterns**：新表，无迁移。
- **回滚**：每个阶段独立提交；`init_schema` 的加列用
  `PRAGMA table_info` 探测，删除列不需要（新增列对旧代码透明——
  旧代码不读新列即无影响）。唯一破坏性面：risk_gate 评分化后
  `deferred_due_to_budget` 语义不变（保留），gate_entries 返回结构
  追加 risk_score 字段（兼容）。
- **验证**：全量测试 + 每个阶段跑对应测试文件。
