# 闭环记录模板规范（记录升级标准，2026-08-12；2026-08-22 全量记录升级）

> 背景：用户实证「记录不能只是形式的记录，本质还是老的模式」——
> 「翻译评价：已产出译文 / 需要优化：否」是空功能；闭环要求全面、
> 记录必须确实有用、有严格标准、根据记录能提升。本规范定义每款
> 游戏三份文档的**实质内容标准**，并随大闭环沉淀持续升级。
>
> 2026-08-22 升级：文本记录导出统一由 `hanhua/core/record_writer.py`
> 单一实现（GUI 与 runner 共享，消除双实现漂移），逐条记录新增
> 对象行/处置行/审核行，新增 text/retranslated.txt 重译档案与
> summary.md 运行记录。见 §1A。

## 0 原则

1. **记录驱动提升**：每份记录必须包含「发现 → 处置 → 沉淀」闭环。
   只描述现象不给出处置和沉淀的段落，视为不合格。
2. **严格标准**：所有结论必须给出判定依据（为什么算合格/不合格），
   不能只写「正常」「通过」。
3. **可追溯**：每个结论指向证据（text 记录/审核报告/测试日志/文件
   :行号）。
4. **实质字段**：翻译评价/需要优化等字段必须是语义审核（reviewer）
   的实质输出，不是形式占位。

## 1A 自动记录文件结构（record_writer 单一实现，2026-08-22）

GUI 手动汉化与 runner 闭环共用同一导出实现，产出结构：

```
docs/all record/<游戏名>/
  summary.md                    # 识别/翻译/审校/写回统计 + 运行记录（请求/Token/耗时/吞吐）
  text/translated.txt           # 成功文本（逐条全字段，见下）
  text/failed.txt               # 失败文本（含失败详情）
  text/skipped.txt              # 跳过文本（含跳过原因分布 + 哨兵告警）
  text/blocked.txt              # 阻断文本（重译未收敛全字段）
  text/retranslated.txt         # 重译收敛档案（★新增：首译→终译对照）
  writeback/writeback.txt       # 文件清单 + 写回结果/闸门
  analysis/analysis-final.md    # 数据快照 + 分析待办清单
  fix record/fix-record.md      # 失败条目明细 + 分类统计
  final report/final-report.md  # 流程结果与结论
  memory-report.md              # 经验记忆（AgentMemory）报告
```

**逐条字段（四类 text 记录统一，质量门原因是核心）**：

| 字段 | 说明 |
|---|---|
| 来源 / 键位 | file_id / key_path 定位 |
| 对象 | Unity 结构定位（组件类型 + asset_file/obj/record_offset/line） |
| 原文 / 译文 | **核心内容**，blocked 译文清空时以 rejected_candidate 留存坏译文 |
| 置信度 / 原因 / 角色 | 识别层元数据 |
| 质量评分 | **质量门原因**（quality_reasons 全列）+ passed 判定 |
| 翻译评价 / 需要优化 | 语义审核实质输出（审核判定不合格时透出问题与建议译文） |
| 写回 | 写回链路视角（已写入 / 未写入(原因) / 回显未执行） |
| 处置 | 闭环视角终态（已发布 / 未发布(原因) / 待处置(阻断/失败/审核待定/审核不合格)） |
| 审核 | 审校终态（review_outcome/level + 风险分），meta 有值才显示 |
| 重译轮次 / 审核理由 / 审核建议 / 失败分类 / 尝试次数 | blocked 专属全字段 |

**retranslated.txt 专档**：语义审核判不合格 → 带反馈重译 → 收敛通过的
条目。逐条含原文 / 首译（被否）/ 重译终译 / 重译原因（质量门原因优先，
审核理由兜底）/ 轮次 / 处置 / 审核 / 审核建议。审核反馈改了什么、
首译→终译对照是审校链路最重要的证据，此前混在 translated.txt 无从
区分，现单独成档。

**不重复原则**：summary.md 只放聚合统计与哨兵；逐条明细只在 text/；
分析结论只在 analysis/。同一信息不出现在两个文件（写回闸门聚合在
summary §3 与 writeback.txt 分工：前者一行结论，后者逐栈/逐项明细）。

**哨兵告警（哑信号 → 可查可告警）**：跳过率 >70%（≥30 条）、回显
豁免 >30%（≥10 条）、单一跳过原因 >90%（≥30 条）、失败率 >40%
（≥15 条）、语言源保留 >30%（≥10 条）、预算耗尽 >60%（≥20 条）、
记忆拒绝率 >50%（≥10 次）、dense 形态跳过 >50%（≥20 条）——异常
比例在 summary.md 第一眼可见。

## 1B analysis/analysis-final.md（分析报告）

必须包含：
1. **失败收敛过程**：每轮失败数 + 失败文本 + 处置（修复/观察项），
   注明确定性（跨轮重跑一致 = 确定性）
2. **失败分类**：每条失败按「判定误杀 / 判定漏豁免 / 模型能力边界 /
   模型波动」四类归档，每类给出判断证据
3. **语义审核结果**（新标准）：引用 review/review-report.md——
   不合格条数、问题分布（术语/语境/专名/语义/风格）、代表性案例
   （如 Resume→简历）、处置（重译/接受/沉淀术语）
4. **正确性复核**：本轮修复的直接证据（run2 中该条由失败转成功）、
   防过宽对照（不掩盖真半翻译）
5. **结论**：已闭环 / 观察项清单（模型边界原文保真不修复的，写明
   升级后重跑验证条件）

不合格形式：只抄写失败清单没有分类；审核不合格项无处置。

## 2 fix record/fix-record.md（修复记录）

必须包含：
1. **触发**：哪款游戏哪条失败暴露（原文/译文/来源），为什么这是
   通用形态不是单游戏特例
2. **形态特征**：可判定的形式化描述（正则/结构/语义特征），
   「真实 X 不以 Y 形态出现」的防误伤边界
3. **实现**：文件:行号 + 接入点（哪一层：识别跳过/翻译/质量门/审核）
4. **判定依据**：为什么这是正确行为（与既有规则对齐的引用）
5. **防过宽**：对照测试（不掩盖真半翻译的反例）
6. **实证**：修复后该游戏重跑结果（失败 → 0 或 → 观察项）
7. **观察项**：不修复的问题记录判断依据（模型边界/波动），写明
   重跑验证条件

不合格形式：只写「修复了 X」没有形态描述；无对照测试。

## 3 final report/final-report.md（最终报告）

必须包含：
1. **概览表**：闭环轮次、翻译条目、失败数（含观察项数）、写回状态
2. **流程结果**：识别/翻译/写回/清理四步的真实数据
3. **质量结论**：
   - 失败分类汇总（判定误杀 0 / 模型边界 N）
   - 语义审核结论（新标准）：审核条数、不合格数、问题分布、处置
   - 术语沉淀（新标准）：本轮审核沉淀的词对数（Resume→继续 等），
     说明后续游戏如何受益
4. **知识库沉淀**：本轮新增 F# 修复、术语词对、观察项——明确
   「后续游戏如何用上」
5. **状态**：✅ 已闭环（写明依据）

不合格形式：语义审核不合格项无处置；沉淀描述
空洞（无词对/无规则）。

## 4 知识库沉淀标准（每轮闭环必须产生）

| 沉淀类型 | 来源 | 去向 | 生效方式 |
|---|---|---|---|
| 判定规则 F# | 失败分类（判定误杀/漏豁免） | batch_translator/quality/placeholders | 代码 + 测试，后续游戏自动生效 |
| 术语词对 | 语义审核（Resume→继续） | glossary.db「审核术语」 | 翻译 prompt 注入，按词对约束 |
| 失败案例 | 失败模式聚合 | knowledge.db | 后续同模式命中提示方案 |
| 观察项 | 模型边界/波动 | fix record 观察项 | 模型升级后重跑验证清单 |

## 5 记录质量检查（文档写完自检）

- [ ] analysis：失败按四类归档且证据充分
- [ ] analysis：语义审核不合格项逐条有处置
- [ ] fix record：每条修复有形态描述 + 防过宽对照 + 实证
- [ ] final report：实机测试逐项结果（含证据路径）
- [ ] final report：术语沉淀词对数（>0 或说明无术语问题）
- [ ] 知识库/术语库实际写入（不是文档里说说）
- [ ] 自动记录（record_writer）：text/ 五类记录齐全（含 retranslated.txt），
      逐条含对象/处置/审核行，质量门原因全列（2026-08-22）
- [ ] summary.md：运行记录（请求/Token/耗时/吞吐）与哨兵告警无异常
      被忽略——有告警必须在 analysis 中给出处置
- [ ] 同一信息不重复出现在两个记录文件（聚合归 summary，明细归 text/）
