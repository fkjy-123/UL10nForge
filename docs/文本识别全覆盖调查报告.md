## 4. 识别缺口（按优先级）

### 4.1 [P0] 未知扩展名文本文件被当 txt 行拆分（写回破坏风险）✅ 已修复
**证据**：containment-breach-hd-edition 的
`StreamingAssets/Language/*.subs`（50 个）与 `languages.langs` 内容为
**JSON**（`{"Cough0": {"subtitle": "*COUGH*"}}`），但 `.subs`/`.langs`
不在 TEXT_EXTENSIONS → `parse_file` else 分支按 txt 行拆分 → 每个
JSON 行拆成半行条目，写回会破坏文件。
**修复（阶段 3）**：`parse_file` 未知扩展名分支改走 `_parse_by_content`
（内容路由），并把 `.subs`/`.langs` 加入 TEXT_EXTENSIONS。

### 4.2 [P0] TextAsset 二进制误当文本（垃圾条目 + 性能）✅ 已修复
**证据**：electric-trains `fp_level_*`（关卡二进制，`6098:1` 行）、
TextAsset 累计 5.6 G 字符含二进制噪声；二进制 decode errors=replace
按行拆分产生大量垃圾条目。
**修复（阶段 3）**：
- 二进制过滤：控制字符（\x00-\x1f 除 \t\r\n）占比 >5% → 整文件跳过
- 数据行过滤：字母密度 <50% 的行占多数 → 关卡/配置数字表跳过
  （fp_level_* 的 `0:12:-1:none` 行 36% 字母实证；字典 `missions=Missioni`
  88% 不误伤）
- 老 Unity TextAsset.m_Script 为 **str**（electric-trains 实证）——
  isinstance 兼容 + surrogateescape 还原（mimic-search/morfosigame/
  the-black-iris 3 游戏修复前全部 UnicodeEncodeError 被吞）

### 4.3 [P1] 自定义二进制格式无字节盲扫兜底 ✅ 已调查（确认无文本）
**证据**：`.caw/.ecm/.sse/.vis/.pos`（`tQ\x10\xad` 魔数，Unity 自定义
序列化，butterflies/captive/inch-by-inch 等 6+ 游戏）、`CRASHLVL`
关卡文件——其中可能含 UTF-8/UTF-16 文本（关卡名/对话），当前完全

**调查结论（阶段 3 全量重扫）**：字节盲扫仅随机噪声，无可译文本；
`.resS/.resource` 为无头原始数据（正常）。维持跳过，无需实现。

### 7.1 老 Unity str m_Script 写回链路（MarioVsLuigi 实证，3 个 bug 修复）

MarioVsLuigi 是首个暴露老 Unity（4.x/5.x）TextAsset.m_Script 为 **str**
字段写回路径的游戏（此前 9 个游戏闭环均为现代架构）。修复：

1. **调用点统一 encode**：str 先 `encode("utf-8-sig", surrogateescape)`
   再按 bytes 处理（startswith/decode 崩溃修复）；
2. **写回赋 str + decode 还原**：UnityPy 保存时对 str 字段
   `encode("utf8", surrogateescape)`（与读取对称）；decode 不能用
   utf-8-sig（会吞掉 BOM 字符 U+FEFF，保存后字节差 BOM，28 对象实测）；
3. **验证用 save_typetree 返回值而非 get_raw_data**：UnityPy 的
   `set_raw_data` 只更新 `self.data`，`get_raw_data` 从原始 reader 读
   ——save 后 get_raw_data 仍返回旧字节（不是保存没生效，是 API 语义），
   28 个 TextAsset 全被误判字节不一致。改为 `obj.save_typetree(data)`
   直接取实际写出字节，与其他分支统一；
4. **immutable 快照排除 m_Script**：TextAsset 的 m_Script 是内容字段
   （有意修改），不是 MonoBehaviour 脚本引用；按不可变字段快照会在
   重开比对时把内容修改误判为脚本绑定被破坏。

### 7.2 闭环验证性能（87MB 游戏卡 25 分钟 → 全流程分钟级）

`_verify_reopen` 的字节搜索对 87MB 游戏逐文件双解码 +
O(files×bytes×segments) 逐段 in 扫描，卡死 25 分钟。三处优化：

1. **中文片段按首字分桶**：finditer 扫一遍文本 + 每中文位置只试同桶
   片段（O(n) 级）；utf-16-le 解码的二进制必有随机中文噪声，「无中文
   早退」对 utf-16-le 无效，分桶是正解；
2. **utf-16 解码搜索上限 8MB**：超大非容器文件（42MB 资源包）不可能是
   译文目标；容器内对象 raw 不受限，译文找回完整；
3. **去掉树级收集**：read_typetree 对无 typetree 的老 bundle 每对象生成
   模板（MonoBehaviour 专属树）极慢；raw 必含树字段序列化字节，
   _check_bytes 双编码搜索已全覆盖，树遍历是冗余。

优化后 379MB 的 BlocksBeyondTheStars 全流程（含两侧重开验证）分钟级完成。

### 7.3 其他发现

- **TAB 分隔 kv 行崩溃**（Daggerfall 实证）：extractor `_extract_txt_text`
  的 kv_structural 分支无条件 `m.group("delim")`，而 `_TAB` 正则没有
  delim 组 → IndexError。修复：与普通 kv 分支一致，TAB 命中时用 "\t"。
- **.fnt 位图字体阻断**（Daggerfall 实证）：写回路由预检检测到 .fnt
  字体且无注入器时正确拒绝写回——位图字体无法注入中文字体，宁可拒绝
  也不显示方块。闭环 harness 将此类阻断与真错误区分（blocked 标记）。
- **闭环跳过原因细分**：区分「无 pending 条目」与「规则翻译未命中
  词汇表」（Neon 实证：识别成功但 _GLOSS 不含其文本）。
