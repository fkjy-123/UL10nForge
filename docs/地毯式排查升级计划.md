## 0.5 运行模式：双游戏并行（用户明确指令，2026-08-11）

- **始终同时跑两个独立游戏**，互不干扰：各自独立 runner 进程、
  独立项目库（`~/.hanhua_sweep/projects/<slug>`）、独立日志、
  独立记录目录（`docs/all record/<游戏名>/`）。
- 流程完全一致：每个游戏都走 1-9 的闭环循环（识别/翻译/写回/记录/
  分析/修复/重测/闭环/清理），不做任何并行特有简化。
- 共享唯一 `llama-server`（10500 单服务）：两条 runner 的请求
  在服务端排队，质量无差异；同一时刻只启动一个服务实例。
- 每个游戏闭环后写三份文档（analysis/analysis-final.md、fix record/、
  final report/final-report.md），删除 `<游戏>_汉化` 只留原版。

## 0.13 runner `--resume` 续跑（基础设施，faerie 中断实证 2026-08-12）

**触发**：faerie 重跑扫描+翻译已完成（store.db 22.6MB，translated

**设计**：`--resume` 续跑模式——项目库存在时跳过扫描+翻译，从语义
审核/写回/导出继续：

1. `run_game(..., resume=True)`：`if resume and not my_dir.exists()`
   → 报错退出（库不存在不能续跑）；`if my_dir.exists() and not
   resume` → rmtree（原强制从零语义保留，重扫语义不变）
2. 扫描块条件化：resume 跳过 scan_all（report=None），直接
   `Project.open_game_dir`；知识库闭环/警告/阻断检查归入非 resume
   分支（`_register_unity_structure` 依赖 report）
3. 翻译块：resume 走 elif 分支——不启动本地模型，加载
   entries + glossary + 伪 stats（store 计数，summary 标注「续跑」）
4. **审核块独立于翻译块**：`if do_review and (do_translate or
   resume)`——runner 中断恢复的主战场正是审核，审核必须可单独续跑
5. `_write_summary` 兼容 report=None：从 store 计数构造伪 report
   （状态分布为真实 store 统计，扫描详情见上轮 summary.md）

**价值**：后续中断（审核超时/断网/杀进程）不再全量重跑——翻译成果
持久化即资产，续跑只补审核/写回/导出。重跑恢复从 4.5h → 审核耗时。

**并发尝试（实测否决）**：给 SemanticReviewer 加 `concurrency=3`

请求排队，反而拖慢。结论：审核吞吐瓶颈在 API 限流而非本地串行；

   throttle/dial/shifter/paddle/pedal/lever/knob 或键位后缀 `:xxx`）+
   原文含方向词（left/right/up/down）+ 译文有中文 → 译文必须含对应
   方向字（左/右/上/下），缺失 → direction_mismatch 失败。兜住删除
   术语后的真错（`Hat Right→正确`、`POV Down-Right→视角：下方`）。

**实证**：2083 失败样本 × 新判定 → 通过 1971（94.6%）+ 仍失败 112
全为真错（方向 98 + 回显 11 + 换行 3）；测试 20 条固化；全量
1646 passed。**教训**：审核沉淀的词对必须带语境保护——单词普通词
（方向/设备词）单字对是污染源信号，组合词对才可全局强制。

**流程变更（用户指令 2026-08-12）**：后续游戏闭环不再做实机测试
（跳过 7 章实测）、不再用云端语义审核（deepseek 审核停用）——失败
收敛以判定层为纲，语义缺陷由术语沉淀与知识库规则承接。

## 0. 核心原则（沿用治理框架）

- **哑信号治理**：跳过是哑的——被跳过的文本必须逐条审视「是否该翻」。
  遵循 `docs/识别形态覆盖与遗漏处理.md` 的 SOP：定位载体形态 →
  证据分层审查 → 真实样本锚点 → 形态登记 → 回归。
- **证据分层**：确定性证据 > 形态性证据 > 猜测性证据；硬结构规则
  任何证据下生效，软猜测规则不得推翻确定证据。
- **闭环才算完**：每个游戏的问题全部修复后，用**升级后的工具版本**
  重跑该游戏全流程直到无问题——绝不用旧版本做下一个游戏。
- **每条记录都有价值**：成功文本查质量与应译性；失败文本查根因；
  跳过文本查是否该翻；写回查成败详情。

## 2. 基础设施（先建，一次投入复用全程）

### 2.1 记录结构 `docs/all record/<游戏名>/`

```
summary.md        # 排查总结：统计/发现的问题/修复项/闭环状态
text/
  translated.txt  # 成功文本：来源/键位/原文/译文/置信度/原因/质量评分
  failed.txt      # 失败文本：来源/键位/原文/译文/失败原因/详情
  skipped.txt     # 跳过文本：来源/键位/原文/跳过原因/判定结论（该翻/不该翻）
writeback/
  writeback.txt   # 写回逐文件记录：文件/成功失败/详情/验证结果
```

格式参照 `docs/fail record/`（来源/键位/原文/译文/原因 五字段）扩展。

### 2.2 runner：`scripts/all_record_runner.py`

单游戏完整流程执行器（复用 GUI 同一条代码路径：Project + BatchTranslator +
LocalModelManager）：

1. 清空项目库（幂等全新建库）→ `scan_all()` → 记录识别统计
   （形态统计/未知形态警告/status/confidence/阻断项）
2. 启动本地模型 → 翻译全部 actionable 条目（真实模型调用）
   → 记录 stats（成功/失败/重试）
3. 导出三类文本记录（translated/failed/skipped，全字段）
4. `write_all()`（真实译文写回）→ 记录逐文件写回详情
5. 汇总 summary.md

### 2.3 速度策略（用户授权：加快但保质量）

- 本地 `llama-server` 单请求串行 → 并发提升无吞吐收益，**速度旋钮是
  `local_batch_size`**（默认 8 → 提到 16 起步）。
- 质量底线：batch 过大长上下文易丢字/回显。每游戏观察 failed 率，
  batch 16 失败率异常上升则回退。
- 模型配置沿用用户设置（settings.json）。

## 3. 单游戏执行流程（闭环循环）

```
1 扫描     scan_all → 记录形态统计/警告/异常
2 翻译     真实翻译全部 actionable → 记录三类文本
3 分析-成功 抽检译文质量与匹配：译文差→翻译质量修复；无关文本→判定跳过（记入 skipped）
4 分析-失败 逐条找根因：系统性彻查（同类问题全解），修复代码+测试+锚点
5 分析-跳过 逐条判定：该翻而跳→识别功能修复（形态/证据分层/先验），防同类遗漏
6 写回     write_all → 逐文件记录；失败→精确定位→根源修复
7 修复回归 修复后跑相关测试 + 用升级版本重跑本游戏全流程
8 闭环判定 无失败/无该翻而跳/写回全绿 → 闭环；否则回到 3-7
9 清理     删除 <游戏>_汉化 输出目录（保留原版），进入下一游戏
```

**版本纪律**：每次修复即递增补丁版本提交（本地）；下一游戏必须用
最新版本跑（修完先提交再继续）。

## 4. 问题分类处理表（分析时的判定标准）

| 类别 | 观察 | 动作 |
|---|---|---|
| 成功-译文质量差 | 译文不通/错译/丢占位符 | 翻译侧修复（prompt/glossary/保护占位符） |
| 成功-无关文本 | 键名/路径/枚举被译 | 识别侧加硬结构规则或证据分层（该文本不该进池） |
| 失败-untranslated | 模型回显 | 该文本该不该翻？该翻→提取侧剔除噪音/结构；不该翻→提取侧跳过 |
| 失败-其他 | 超时/格式错 | 按原因分类，系统性修复 |
| 跳过-该翻 | 对话/UI 未进池 | 识别侧修复：形态先验/证据分层/提取器覆盖；登记形态锚点 |
| 跳过-不该翻 | 键名/引擎串/结构 | 无需动作（记录判定） |
| 写回-失败 | 某文件写回错 | 定位 writer 代码路径，根源修复 + 回归测试 |

每项修复遵循：**根因定位 → 代码修复 → 单测/锚点 → 全量回归 → 该游戏重测闭环**。

## 6. 风险与约束

- **时长**：~120 游戏 × 每游戏 30-90 分钟（翻译为主）——双游戏并行
  推进（见 0.5），每对游戏闭环后再进下一对，进度记录在 summary 与本
  文档 0.6。

- **用户中断**：任何一步用户叫停即停；已闭环游戏记录保留，断点续作。
