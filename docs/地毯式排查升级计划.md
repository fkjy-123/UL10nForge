## 0. 核心原则（沿用治理框架）

- **哑信号治理**：跳过是哑的——被跳过的文本必须逐条审视「是否该翻」。
  遵循 `docs/识别形态覆盖与遗漏处理.md` 的 SOP：定位载体形态 →
  证据分层审查 → 真实样本锚点 → 形态登记 → 回归。
- **证据分层**：确定性证据 > 形态性证据 > 猜测性证据；硬结构规则
  任何证据下生效，软猜测规则不得推翻确定证据。
- **闭环才算完**：每个游戏的问题全部修复后，用**升级后的工具版本**
  重跑该游戏全流程直到无问题——绝不用旧版本做下一个游戏。
- **每条记录都有价值**：成功文本查质量与应译性；失败文本查根因；
  跳过文本查是否该翻；写回查成败详情。

## 2. 基础设施（先建，一次投入复用全程）

### 2.1 记录结构 `docs/all record/<游戏名>/`

```
summary.md        # 排查总结：统计/发现的问题/修复项/闭环状态
text/
  translated.txt  # 成功文本：来源/键位/原文/译文/置信度/原因/质量评分
  failed.txt      # 失败文本：来源/键位/原文/译文/失败原因/详情
  skipped.txt     # 跳过文本：来源/键位/原文/跳过原因/判定结论（该翻/不该翻）
writeback/
  writeback.txt   # 写回逐文件记录：文件/成功失败/详情/验证结果
```

格式参照 `docs/fail record/`（来源/键位/原文/译文/原因 五字段）扩展。

### 2.2 runner：`scripts/all_record_runner.py`

单游戏完整流程执行器（复用 GUI 同一条代码路径：Project + BatchTranslator +
LocalModelManager）：

1. 清空项目库（幂等全新建库）→ `scan_all()` → 记录识别统计
   （形态统计/未知形态警告/status/confidence/阻断项）
2. 启动本地模型 → 翻译全部 actionable 条目（真实模型调用）
   → 记录 stats（成功/失败/重试）
3. 导出三类文本记录（translated/failed/skipped，全字段）
4. `write_all()`（真实译文写回）→ 记录逐文件写回详情
5. 汇总 summary.md

### 2.3 速度策略（用户授权：加快但保质量）

- 本地 `llama-server` 单请求串行 → 并发提升无吞吐收益，**速度旋钮是
  `local_batch_size`**（默认 8 → 提到 16 起步）。
- 质量底线：batch 过大长上下文易丢字/回显。每游戏观察 failed 率，
  batch 16 失败率异常上升则回退。
- 模型配置沿用用户设置（settings.json）。

## 3. 单游戏执行流程（闭环循环）

```
1 扫描     scan_all → 记录形态统计/警告/异常
2 翻译     真实翻译全部 actionable → 记录三类文本
3 分析-成功 抽检译文质量与匹配：译文差→翻译质量修复；无关文本→判定跳过（记入 skipped）
4 分析-失败 逐条找根因：系统性彻查（同类问题全解），修复代码+测试+锚点
5 分析-跳过 逐条判定：该翻而跳→识别功能修复（形态/证据分层/先验），防同类遗漏
6 写回     write_all → 逐文件记录；失败→精确定位→根源修复
7 修复回归 修复后跑相关测试 + 用升级版本重跑本游戏全流程
8 闭环判定 无失败/无该翻而跳/写回全绿 → 闭环；否则回到 3-7
9 清理     删除 <游戏>_汉化 输出目录（保留原版），进入下一游戏
```

**版本纪律**：每次修复即递增补丁版本提交（本地）；下一游戏必须用
最新版本跑（修完先提交再继续）。

## 4. 问题分类处理表（分析时的判定标准）

| 类别 | 观察 | 动作 |
|---|---|---|
| 成功-译文质量差 | 译文不通/错译/丢占位符 | 翻译侧修复（prompt/glossary/保护占位符） |
| 成功-无关文本 | 键名/路径/枚举被译 | 识别侧加硬结构规则或证据分层（该文本不该进池） |
| 失败-untranslated | 模型回显 | 该文本该不该翻？该翻→提取侧剔除噪音/结构；不该翻→提取侧跳过 |
| 失败-其他 | 超时/格式错 | 按原因分类，系统性修复 |
| 跳过-该翻 | 对话/UI 未进池 | 识别侧修复：形态先验/证据分层/提取器覆盖；登记形态锚点 |
| 跳过-不该翻 | 键名/引擎串/结构 | 无需动作（记录判定） |
| 写回-失败 | 某文件写回错 | 定位 writer 代码路径，根源修复 + 回归测试 |

每项修复遵循：**根因定位 → 代码修复 → 单测/锚点 → 全量回归 → 该游戏重测闭环**。

## 6. 风险与约束

- **时长**：~120 游戏 × 每游戏 30-90 分钟（翻译为主）——分批推进，
  每游戏闭环后再进下一个，进度记录在 summary。
- **模型质量波动**：失败率高时优先查 batch 设置，其次查文本噪音源头。
- **硬盘**：每游戏闭环即删汉化输出，只留原版。
- **用户中断**：任何一步用户叫停即停；已闭环游戏记录保留，断点续作。
