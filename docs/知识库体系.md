# 知识库体系（六库架构，v0.25.0）

> 2026-08-11 升级完成。单个 SQLite 表（`knowledge_items`）+ 六域 + 结构化
> note，支撑识别→翻译→质量→写回全链路的知识沉淀与复用。
> 查询 CLI：`python scripts/kb_query.py`；种子入库：`python scripts/kb_seed_docs.py`。

## 1. 六库总览

| 域 domain | 库名 | 内容 | 主要 kind |
|---|---|---|---|
| `unity_structure` | ① Unity 结构库 | Unity 版本特征、资源类型、文本位置、检测方法、提取方案、已知问题 | unity_version / resource_type / text_location / detect_method / extract_plan / known_issue |
| `fail_case` | ② 失败案例库 | 历史失败案例（FAIL 编号、根因、解决方案） | 翻译 / 识别 |
| `text` | ③ 文本规则库 | 文本类型判定与处置（翻/留/跳） | ui_text / dialogue / skill / equipment / achievement / system_msg / debug / param / code / loaned_word / proper_name / uppercase_action / spaced_action / multilingual_source / interaction_prompt / platform_name |
| `component_compat` | ④ 组件兼容库 | 组件级兼容问题与修复（TMP/Text/输入/字体） | text / textmeshpro / input_system / font / dropdown / ui_toolkit / others |
| `quality` | ⑤ 翻译质量库 | 常见错误、术语一致性、质量门规则、评分案例 | common_error / term_consistency / quality_gate / scoring_case |
| `writeback` | ⑥ 写回验证库 | 写回案例、格式要点、测试流程 | writeback_case / format_note / test_flow |

功能域：`file`（文件形态）、`rule`（判定规则）——BUILTIN_RULES 内部域。

## 2. 数据模型

单表 `knowledge_items`（`~/.hanhua/knowledge.db`）：

| 列 | 说明 |
|---|---|
| domain / kind | 域与子类（六库索引） |
| pattern | 模式/案例描述（幂等键：domain+kind+pattern） |
| action | 处置（translate / keep / skip / info / replace_font / rebind_font_asset / context_judge …） |
| map_to | 译例对照（并入 glossary references，翻译时注入） |
| note | 结构化 JSON（fail_case）或自由文本+来源标注 |
| hits | 命中次数（复用自动累加） |
| source | seed / manual / auto（种子/人工沉淀/自动学习） |
| game | 沉淀来源游戏（溯源与按游戏统计） |
| created_at / updated_at | 时间戳 |

schema 升级策略：`PRAGMA table_info` + `ALTER TABLE ADD COLUMN` 兼容扩展，
**绝不重建**（已有库原地升级）。

## 3. 失败案例 note 格式（结构化 JSON）

```json
{"fail_no": "FAIL-00067", "game": "…", "env": "Unity", "issue": "…",
 "phenomenon": "…", "root_cause": "…", "solution": "…", "impact": "…",
 "fixed_version": "…", "fail_type": "翻译"}
```

- fail_no 全局唯一（`renumber_cases()` 幂等重编号 FAIL-00001 起）
- 旧管道格式（`FAIL-00067|游戏:x|环境:y|…`）由 `migrate_legacy_notes()`
  自动迁移，幂等
- 翻译失败自动沉淀：`record_case(..., source="auto")`，识别复用：
  `match_case(problem, fail_type)` 打分制检索

## 4. 检索接口（KnowledgeBase）

| 方法 | 用途 |
|---|---|
| `list_knowledge(domain, kind)` | 查询（内置种子+持久库合并，hits 降序） |
| `search_keyword(keyword, domains)` | 跨库全文检索（pattern/map_to/note） |
| `match_case(problem, fail_type, limit)` | 失败案例智能复用（整串+3、拆分词+1、中文 bigram 滑窗） |
| `solve(problem, limit_each)` | 六库联动检索——一个问题返回六库全部答案 |
| `library_stats()` / `game_stats()` | 统计 |
| `learn()` | 自动学习（source=auto） |
| `format_reference_pairs()` | 译例对照（并入 glossary，翻译时 terms 注入） |
| `format_for_prompt()` | 特殊规则注入 system prompt |

## 5. 数据来源

- **内置种子**（BUILTIN_RULES，代码内）：抽象判定规则，零成本确定性识别
- **docs 种子**（106 条，source=seed）：`scripts/kb_seed_docs.py`，从五份指南
  （全景指南 / 资料大全 / 识别形态 / 写回资料 / 安全写回与本地模型质量指南）
  提取，注明来源（如 `来源:全景指南:4.2`），幂等
- **自动沉淀**（source=auto）：runner 闭环三接入点——
  - 扫描后：Unity 版本/资源类型 → unity_structure（fingerprint）
  - 失败时：`record_case` 沉淀 + `match_case` 复用历史方案
  - 写回后：结果/错误 → writeback

## 6. runner 闭环接入

`scripts/all_record_runner.py`：

```python
# 扫描后：结构知识注册（fingerprint_game 获取 Unity 版本/runtime）
_register_unity_structure(kb, game_name, game_dir, report)
# 失败案例：沉淀 + 检索复用
case_kb.record_case(game=..., fail_type=..., problem=..., root_cause=..., fix=...)
for past in case_kb.match_case(src, limit=2): ...   # 打印 fail_no/game/solution
# 写回后：结果注册
_register_writeback(kb, game_name, result, error)
```
