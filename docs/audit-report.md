# 全链路框架审计报告（2026-08-12）

四路并行审计（识别管线/翻译质量/写回安全/插件运行时+闭环流程），共 38 个弱点，
合并同源项后框架性问题 16 个，全部挂在 3 个根因模式之下。

## 三个根因模式

**根因 A：规则补丁化——if-elif 代码行序 = 证据优先级**
每个游戏的新形态在判定链尾加一个分支，新分支插队就改变所有旧规则的优先级。
证据分层原则只写在注释里，实现是补丁顺序。测试盲区：单个规则有测试、规则间
顺序交互无测试——回归时测试全绿。

**根因 B：防护写而不生效——机制存在但从未运行**
写回侧读的元数据键名与提取侧写入的键名不一致（死代码）；运行时插件不受静态
写回的逻辑审计约束。规则写了、测试过了、但实际拦截从不触发——「按键失灵
反复出现」的直接机制原因。

**根因 C：无反馈闭环——失败不可查、不可分类、不反哺**
识别层跳过的条目静默丢弃（哑信号，无留档）；翻译失败 16 个原因平铺无分类、
每轮全量重跑同一条链；记忆放大错误；翻译层不反哺识别层。

### 识别管线（5 个）
