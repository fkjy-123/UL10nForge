剩余缺陷（按严重度）\n\n**C1（P0）回退/一致性条目的闸门双重记账**。`note_logic_reverted` 只调 `note_attempt`（writer.py:194-205），未加入 `_resolved_locators`；write_back_v2 尾部循环（writer.py:820-825）对未 resolve 的候选统一 typetree/rawstr 补丁对象以**补丁后字节**为 expected（自证），独立防线仅 immutable 字段快照（同一 UnityPy 解析器=同源盲区）+ 字符串序列重扫（同一扫描器）。typetree 完整重建（save_typetree）重写整个对象，非目标字段（数值/数组长度/类型名）只靠 `_IMMUTABLE_FIELD_NAMES` 覆盖；若 UnityPy 序列化缺陷静默损坏某字段，重开验证发现不了（doubleshake F15 实证此类检查既会误报也有漏报面）。\n\n**C3（P0）IL2CPP v39 重开验证只比对被改记录**（writer.py:1496-1506）：按顺序配对只检查 expected 条目；紧凑重建后**未补丁记录**的内容/位置无逐条比对。重建逻辑在末条之后的错误（空洞清零越界、游标偏差）若仍保持合法 UTF-8 与结构，会静默通过。\n\n**C4（P1）W3 排除表不覆盖 rejected 条目**。插件翻译表来自 `_runtime_exact_translations`（project.py:1306，写回前按 DB 生成），仅排除 `logic_reverted_sources`；被写回侧拒绝的条目（immutable_field_protected/field_path_value_mismatch/object_read_failed 等）**原文保留在静态层、却被插件运行时翻译**——正是 W3 想封的「静态保留原文、运行时断链」模式对 rejected 类复发。另外截断条目：静态写截断版、插件写全量版，两处文本不一致。\n\n**C5（P1）font_replace 二次重建使 Addressables CRC 失效**。catalog CRC 在 write_back_v2 末尾更新（writer.py:828），随后 install_static_fonts 又整容器重建 bundle 并 `os.replace`（font_replace.py:299-309）→ bundle CRC 再次变化，catalog 无二次更新、字体替换后也无容器级重开验证。Addressables 管线 + 字体替换同时命中的游戏会 CRC Mismatch 拒载。\n\n**C6（P1）四态闸门盲区**。(a) **无启动冒烟**：write_all 无 smoke 参数（指南 §7 级疑似键照写，报告与行为一致但阈值不联动。\n\n**C7（P1）备份/回滚缺口**。单级回滚（只留上次备份）；manifest（回滚凭据）在 rename **之后**写入（project.py:1609-1612），rename 与写 manifest 之间存在崩溃窗口丢凭据；发布 rename 成功后若后续异常，finally 分支 rmtree
