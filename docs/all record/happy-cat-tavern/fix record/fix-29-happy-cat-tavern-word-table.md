# fix-29 打字游戏词表对象整体跳过（happy-cat-tavern 实证 2026-08-12）

## 现象

happy-cat-tavern（打字游戏）第一轮 197 条翻译 0 失败，但词表对象
level1#1311（1700 条字符串）中白名单常见词（play/time/gold/size…
）被 `direct_code_signal`/`ui_control_signal` 误放行进池翻译并写回
——玩家按英文打字时看到的是中文词，**打字玩法被破坏**。

## 根因

打字游戏单词库对象：字符串几乎全部是单 token 单词且数量大（1700 条
100% 单词）。对象级特征被形态性猜测（白名单显示词信号）击穿——白名单
显示词证据本意是「真实 UI 组件对象里的词」，但词表对象里同样的词被
同一信号放行。

## 修复（hanhua/core/unity/extractor.py）

1. **对象级判定** `is_word_table`：非引擎字符串池 ≥50 条且 ≥95% 匹配
   `^[A-Za-z]+$`（单 token 纯字母单词）→ 词表/字典结构。大型全单词
   数组是确定性词表结构证据，优先于形态性猜测（证据分层）。
2. **循环分支**：`if is_word_table:` → 整对象 `word_table_object`
   跳过（含白名单词——白名单显示词证据只在真实 UI 组件对象生效）。
3. 阈值防误伤：<50 条小对象（正常 UI 设置菜单）、含句式的大对象
   （单词占比被拉低 <95%）不触发。

## 验证（第二轮）

- 识别条目 197 → 180（词表 1700 条整对象退出）
- 翻译 180 条 0 失败（记忆命中 3、直接应用 3 采纳）
- 词表词（play/time/gold/size…）全部不再进池
- 观察项：size 单串对象（obj 1131）仍在池内——单串无对象级证据，
  保持 pending 属识别层能力边界，无破坏风险

## 测试

tests/test_f29_word_table.py（4 测试）：
- 大词表整对象跳过（含白名单词）
- 小词表不触发
- 大对象含句式不触发
- 正常 UI 对象不受影响
