# minato 口口缺字——逐 Unicode Code Point 全链验证诊断

日期：2026-08-14
任务：#12（minato 口口缺字彻底解决）+ #42（防复发防御层）

## 结论（TL;DR）

minato 的口口**不是字体缺字形（Case A），而是整层缺失（Case H）**：
汉化写回只写了文本（metadata 字符串），**从未部署任何字体层**——主字体、
fallback、TMP Font Asset 全部不存在。因此需求集全部 902 个码点沿
Font→Character→Glyph→Atlas→Fallback 链在第 0 步断掉。

要根治需要两步：**文本写回**（metadata 中文补全）+ **字体部署**
（IL2CPP x64 需 BepInEx 6/Il2CppInterop 载荷注入，当前无该载荷）。

## 根因链（多层，非单点）

1. **写回层**：汉化副本 `D:\游戏\minato_汉化` 已不存在（2026-08-14 01:20:36 写回后未保留）；
   写回记录显示 588 条写入、metadata 5294 条「无译文条目」（IL2CPP 写回未执行中文补全）。
2. **字体层**：写回记录 `字体层级：unsupported`——IL2CPP x64 无 BepInEx 6/Il2CppInterop
   载荷，静态字体替换管线无法注入 → 无 TTF 可安装 → 无 FontSource 可验证。
3. **结果**：游戏运行时用原字体渲染中文 → 原字体（日/英文）无 CJK 字形 → 口口。
4. **前置防复发缺口**：此前管线对「字体层缺失」无显式告警（识别是哑信号，缺形态化清单）。

## 修复路径（用户侧，需实机条件）

1. **文本**：重建汉化副本 → 重新写回 metadata（补全 5294 条无译文条目）→ 保留副本。
2. **字体**：为 IL2CPP x64 准备 BepInEx 6 + Il2CppInterop 载荷（或等效注入方案），
   使静态字体管线可达；安装覆盖 779 CJK + 7 全角 + 3 CJK 标点的 TTF（如思源黑体
   SourceHanSansSC），其余 16+2 稀有码点交给系统 fallback。
3. **验证**：`verify_chain(需求集, font=已装TTF, fallbacks=(系统fallback,))`
   → 报告 902 码点全部 OK 后才可发布；任一断点按 Case 字母处置。
4. **防复发**：诊断脚本纳入游戏闭环检查清单——每次汉化后跑一遍，
   断点 > 0 即阻断发布（与 #42 自检同语义：不假 PASS）。

## 与验收计划的关系

第十八阶段（逐 Unicode Code Point 全链验证）已按计划落地：
- Case A（缺字形）、B（字符表/字形表缺）、C（消费端配置）、D（fallback 未配置）、
  E（fallback 缺字形）、F（动态字体运行时 attest）、G（图集断）、H（文件无效）、
  DATA_CORRUPTION（方框码点已写入）全部可实现判定并有测试证据。
- minato 实测 = Case H 全断（无字体层），与写回记录「字体层级 unsupported」一致，
  交叉印证了诊断与既有记录的真实性。
