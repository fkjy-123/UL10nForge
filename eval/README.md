## 指标

### 记录回测（`--record-stats N`，默认 3，零模型成本）

从闭环记录的 review.json + summary.md 聚合：

- **污染率** = flagged / reviewed——审核判定「不合格」占比（送审条数口径）
- **审核覆盖率** = reviewed / translated——已翻译条目中被语义审核覆盖的比例
- **复用收益** = 记忆直接应用（翻译阶段）+ 术语沉淀（词对入全局库）
- **收敛率**：口径缺口——闭环记录未落盘重译收敛数据（runner 未记
  review_failures 收敛计数），如实标注；由 `--live` 或 runner 补记

### 固定集 live 评估（`--live`，本地审核模型）

对固定集逐条过 SemanticReviewer（Qwen3.5-4B，本地，非云端）：

- 错译集**检出率** = flag 判定 / 有译文条数（审核对真实错译的捕获能力）
- 正确集**误报率** = flag 判定 / 200（好译文被冤枉的比例）
- 多义词**消歧通过率**（pass 语境译文应通过）与**坏译检出率**（flag 语境
  译文应检出）
- 判定错误明细 → `results/live_errors.jsonl`（供人工复核）

## 首批结果快照（2026-08-13）

### 记录回测：最近 3 款闭环

| 游戏 | 审核 | 不合格 | 污染率 | 已翻 | 覆盖率 | 记忆命中 | 术语沉淀 |
|---|---|---:|---:|---:|---:|---:|---:|

| interdream | 571 | 228 | 39.9% | 3848 | 14.8% | 0 | 11 |

| **聚合** | **2057** | **685** | **33.3%** | **14544** | **14.1%** | **10** | **100** |

解读：
- 33.3% 污染率是**送审子集**口径（discretionary 受 15% 送审率上限约束）；
  三款均 >20%——审核确实在捕获大量真实错译，机械质量门无法覆盖
  （语义/术语/语境类错误）。
- 覆盖率 14.1% ≈ 送审率上限（balanced 15%）——覆盖受预算约束，这是
  有意的分级策略（mandatory 通道不受限）。
- 复用收益：10 条记忆直接应用 + 100 条词对沉淀全局库，后续游戏按词对
  约束翻译（收益在下一款游戏兑现，持续累计）。

### 固定集 live 评估（Qwen3.5-4B-Q4_K_M，2026-08-13）

| 指标 | 结果 | 解读 |
|---|---|---|
| 错译集检出率 | **178/196 = 90.8%** | 审核捕获 9 成真实错译（语义/术语/语境类——机械质量门无法覆盖） |
| 正确集误报率 | **17/200 = 8.5%** | ~8.5% 好译文被冤枉标记「需优化」（人工确认负担 + 潜在写回阻塞，见下） |
| 多义词消歧通过率 | 6/12 = 50% | pass 语境译文只有一半被放行——审核对「同原文不同语境」敏感，但会误伤 |
| 多义词坏译检出率 | 8/12 = 66.7% | flag 语境译文 2/3 被检出 |

**误报 8.5% 分析**（live_errors.jsonl 共 45 条供人工复核）：
- 误报有真实成本：MAJOR/CRITICAL 判定使好译文进入人工队列（不可写回），
  需要在审查队列中人工放行；
- 本轮全量样本（200）误报率 8.5% vs 首轮子集（165）1.2%——新增样本
  集中了判罚更严的条目（语气/术语轻微偏差被升级为 flag），口径以全量为准；
- 建议（P2）：审核 prompt 区分「必须修正」（语义错误/术语错误）与
  「建议优化」（语气/风格轻微问题），后者降级 MINOR 不入阻塞。

## 口径与约束

- 固定集全部来自真实闭环记录（8 款游戏 2026-08-13），非合成数据；
- 免实机测试/免云端审核（2026-08-12 用户指令）：live 评估只用本地
  审核模型，不触碰云端；
- 向量标注 = 审核终态代理（pass 全对 → 可复用），非人工逐条标注——
  已如实说明，供后续人工抽查升级；
- 收敛率缺口的修复：runner 把 review_failures 的 converged 计数写入
  summary.md（后续闭环自然补上）。
